| 项 | 内容 |
|---|---|
| 原始诉求 | 「将项目落地可以下载的软件，如 Windows、移动端版本；Web 端期末要答辩，不能动 `web-lostfond`」 |

| 复用策略 | 把 Web 前后端源码复制为独立基线，只在 App 工程内做「可移植化」改动，改动不回流 Web |

> 结论：Web 版与 App 版是两条独立发布线，共用同一套业务代码基线，但配置、构建产物、运行数据完全分离。

## 三、总体架构

**Windows 版（双击即用，单进程安装）**

```text
shiguang.exe（Electron 33.4.11）
  ├─ 单实例锁：第二次启动只聚焦已有窗口
  ├─ 启动画面（splash）
  ├─ runtime\bin\java.exe（jlink JRE 21.0.10，约 51 MB）
  ├─ lost-found-backend.jar（57.7 MB，profile=app）
  │    ├─ H2 文件库：%APPDATA%\Shiguang\data\db\lost_found.mv.db
  │    ├─ 上传目录：%APPDATA%\Shiguang\data\uploads
  │    └─ 同源托管 frontend-dist、/api、/uploads
  └─ BrowserWindow → http://127.0.0.1:18080/
```

**Android 版（Capacitor WebView）**

```text
Capacitor WebView（本地 dist，androidScheme=http，hash 路由）
  └─ axios → http://<电脑局域网 IP>:18080/api
```

- 手机端**不内置后端**，连接正在运行的 Windows 版；两端共用同一 H2 数据库与上传目录。
- 电脑端退出后手机端不可用；电脑换网络后局域网 IP 会变化，需要在「服务器设置」中更新。

### 4.2 后端独立化（H2）

#### 4.2.1 新增 `application-app.yml`

[application-app.yml](../../../../App-LostFond/backend/src/main/resources/application-app.yml) 是独立版唯一入口配置：

| 配置 | 值 | 说明 |
|---|---|---|
| `server.port` | `${SERVER_PORT:18080}` | Electron 自动选空闲端口后覆盖 |
| `server.address` | `${SERVER_ADDRESS:0.0.0.0}` | 手机可通过局域网访问 |
| JDBC URL | `jdbc:h2:file:${APP_DATA_DIR:./app-data}/db/lost_found;MODE=MySQL;DATABASE_TO_LOWER=TRUE;NON_KEYWORDS=...;DB_CLOSE_ON_EXIT=FALSE` | MySQL 兼容模式 |
| `spring.sql.init.schema-locations` | `classpath:db/schema-h2.sql` | 每次启动幂等建表 |
| `file.upload-dir` | `${APP_DATA_DIR:./app-data}/uploads` | 与 Web 版上传目录同结构 |
| `web.cors.allowed-origins` | `http://localhost,http://127.0.0.1,capacitor://localhost,https://localhost` | 覆盖 Capacitor WebView 源 |
| `seed.admin-password` / `seed.user-password` | `Admin@2026` / `Demo@2026`（可被环境变量覆盖） | 首次播种演示账号 |
| `jwt.secret` | `${JWT_SECRET:}` | 手动运行时必须提供；Electron 自动生成 |
| `knife4j` / `springdoc` | 关闭 | 桌面/手机端不需要接口文档 |

#### 4.2.2 新增 `schema-h2.sql`

- 与 MySQL 版 `schema-init.sql` 保持 **10 张表**：`user`、`item`、`item_image`、`claim_record`、`message`、`admin_log`、`favorite`、`delivery`、`watch_subscription`、`watch_target`。
- 去掉 MySQL 专有语法（`ENGINE`、`CHARSET`、内联 `KEY`、列 `COMMENT`），保留业务唯一约束（如账号唯一、一人一条守望订阅）。
- 全部使用 `CREATE TABLE IF NOT EXISTS`，重复启动不报错、不清数据。
- JDBC URL 必须带 `NON_KEYWORDS=USER,VALUE,TYPE,STATUS,ACTION,CYCLE,KEY`，否则 `user`、`status`、`cycle` 等表名/列名会与 H2 保留字冲突。

#### 4.2.3 pHash 查询改为 Java 侧计算

- 删除 `ItemImageMapper.searchByHash()` 中的 MySQL 专有 SQL：`MIN(BIT_COUNT(phash ^ ?))`。
- `SearchService.searchByHash()` 改为：
  1. `selectList` 取所有非空 `phash`；
  2. `Long.bitCount(img.getPhash() ^ q)` 逐图算汉明距离；
  3. 按 `itemId` 取最小距离；
  4. 阈值过滤、距离升序；
  5. **先做审核/下架可见性过滤，再截断 Top-N**。
- 原因：同一份代码要同时跑 MySQL 与 H2，避免位运算方言差异；演示库只有几十到几百张图，全表扫描 + `bitCount` 足够快。
- 顺带修正：原 SQL 的可见性过滤在 `JOIN item` 内完成；改成 Java 侧后，把可见性过滤放在 `topN` 截断之前，避免待审核/已下架启事占用名额。

#### 4.2.4 种子与演示口令

- `pom.xml` 增加 `com.h2database:h2`（runtime）；JImageHash 自带的 H2 依赖继续排除。
- `DataInitializer` 的演示口令打印条件从 `local` 扩展为 `local, app`，方便桌面版首次启动在日志中看到账号。
- 种子仍读取 `uploads/seed/manifest.json`：20 个用户、60 条启事、120 条图片记录（30 张底图复用 + 缩略图）。

#### 4.2.5 构建产物

```bash

mvn -DskipTests clean package
# target/lost-found-backend.jar，57,704,702 B
```

## 五、问题与修复

### 5.1 P0：Windows 1.0.0 安装后双击无反应

**现象**

- 用户安装 1.0.0 后双击桌面「拾光」，没有任何窗口、没有进程、也没有日志。
- 安装目录为 `D:\新建文件夹\新建文件夹\shiguang-desktop`；桌面/开始菜单快捷方式均指向该目录下的 `拾光.exe`。

**定位过程**

1. 直接运行 exe、`Start-Process` 均失败；进程创建返回 `-2147483645`（`0x80000003`），说明进程在创建阶段就被拦截，而不是应用内部报错。
2. 把同一套文件复制到纯 ASCII 路径可启动；复制到另一个中文路径也可启动 → 不是单纯的「中文路径」问题。
3. 检查目录 ACL：原目录带有第三方安全软件的「文件夹保护」标记。联想电脑管家（火绒引擎）会拦截受保护目录中的**未签名可执行文件**。
4. 1.0.0 安装包允许选择安装目录并可选「所有用户」，用户恰好选到了受保护目录，于是出现静默失败。

**修复（1.0.1）**

| 项 | 1.0.0 | 1.0.1 |
|---|---|---|
| 安装方式 | 可选目录 / 可选所有用户 | `oneClick: true` 一键安装 |
| 权限 | 可能触发管理员 | `perMachine: false`、`allowElevation: false` |

### 5.2 Windows 包打开后停在「服务器设置」

**现象**：1.0.1 首次打包后，Windows 版启动进入的是手机端的「服务器设置」页，而不是首页。

**根因**：`frontend/dist` 里留的是上一次 Android 构建的产物（hash 路由 + 服务器设置守卫）；electron-builder 只负责打包现有 `dist`，不会自动重建。

**修复**：

- `build-dist.mjs` 在调用 electron-builder 前强制执行 `npm run build:electron`；
- README 明确警告：不要在 Android 构建后直接运行 `electron-builder`；
- 重新打包后窗口标题为「拾光 · 让每一件失物都能回家」，首页正常。

### 5.3 打包报 EBUSY（`Softeare/win-unpacked/resources/app.asar`）

**根因**：electron-builder 原本直接输出到 `Softeare/`，而 `Softeare/win-unpacked` 中的 `app.asar` 被运行中的程序/安全软件占用，导致清理旧目录失败。

**修复**：

- `directories.output` 改为 `../build/out`；
- 打包完成后只把安装包复制到 `Softeare/`；
- 后续如需清理，关闭「拾光」并等安全软件扫描结束后再删除 `win-unpacked`。

### 5.4 Android 海报导出失败（canvas 被污染）

**根因**：Android 页面来自 WebView 本地包，图片来自另一台主机；`<img>` 未声明 CORS 时，canvas 被标记为 tainted，`toDataURL()` 抛安全错误。

**修复**：`PosterDialog.vue` 的 `loadImage()` 设置 `im.crossOrigin = 'anonymous'`；同时后端 `/uploads/**` 允许跨域。海报导出改走 `saveDataUrl()`，原生端写入缓存后调起系统分享面板。

### 5.5 H2 方言与保留字

- H2 不认 MySQL 的 `BIT_COUNT` / `^` 写法 → pHash 改 Java 侧计算（见 4.2.3）。
- `user`、`status`、`cycle` 等是 H2 保留字 → JDBC URL 增加 `NON_KEYWORDS`。
- MySQL 的 `ENGINE`、`CHARSET`、内联 `KEY`、列 `COMMENT` 在 H2 下会报错 → `schema-h2.sql` 单独维护，保留约束、去掉方言。

### 5.6 端口冲突

- Web 版后端默认 8080；桌面版使用 18080，并在 `18080–18099` 内自动顺延，避免被本机其他进程占用。
- 手机端连接地址中的端口必须与「服务信息」显示的一致。

## 八、注意事项（后续改这块必看）

1. **Windows 打包前必须先构建 Electron 模式前端**：直接跑 `electron-builder` 可能把 Android 版 `dist` 打进安装包（表现为打开「服务器设置」）。统一走 `cd App-LostFond/desktop && npm run dist`。
2. **NSIS 的 oneClick + per-user 是有意设计**：不要改回可选目录 / `perMachine`。未签名程序装在中文路径或联想电脑管家/火绒保护的目录会被拦截，用户看到的就是「双击没反应」。
3. **不要让用户手动移动安装目录**：需要换位置时重新运行安装包；移动后快捷方式和更新都会失效。
4. **运行数据在 `%APPDATA%\Shiguang`**：`data`（H2 + 上传图片）、`logs\backend.log`、`jwt.key`。卸载程序不会删除这些目录；重置演示数据 = 退出后删除 `data`。
5. **H2 与 MySQL 建表脚本要同步**：以后新增表/字段，`schema-h2.sql` 与 `schema-init.sql` 两边都要改；H2 侧避免 MySQL 方言。
6. **pHash 查询不要改回 `BIT_COUNT(phash ^ ?)`**：H2 不支持；`SearchService` 的 Java 侧实现已经兼顾阈值、排序和可见性过滤。
7. **可见性过滤必须在 Top-N 截断之前**：否则待审核/已下架启事会占掉名额，用户看到的匹配结果变少。
8. **手动启动后端必须提供 `JWT_SECRET`**：`application-app.yml` 的默认值为空；Electron 会自动生成并写入 `jwt.key`。
9. **Android 签名文件不要提交/分发**：`frontend/android/keystore.properties` 与 `shiguang-release.keystore` 仅保留在本机；丢失证书将无法覆盖升级已安装的 APK。
10. **手机端依赖电脑端**：电脑退出后手机不可用；电脑换 Wi-Fi 后局域网 IP 变化，需要在手机「服务器设置」中更新。
11. **Android 的 `androidScheme: 'http'` + `cleartext: true` 是为了局域网 HTTP**：如果以后改用 HTTPS/公网隧道，需要同步调整 CORS 与地址。
12. **安装包未做商业代码签名**：Windows SmartScreen / 手机管家可能提示风险，课程演示场景选择继续安装即可。
13. **`Softeare` 只放最终交付物**：electron-builder 的中间产物在 `build/release`（2026-10-22 起；此前为 `build/out`）；不要把 `win-unpacked` 当成可分发目录。
