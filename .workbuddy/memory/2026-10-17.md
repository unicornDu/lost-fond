## git add . 误入库诊断（待修）
- 现象：`git add .` 输出大量 `LF will be replaced by CRLF`（core.autocrlf=true，本身无害），但暂存区共 11869 文件。
- 根因：根目录无 .gitignore；lost-found/.gitignore 未覆盖 `_android-sdk/`、`desktop/release*/`、`frontend/android` 构建产物。
- 统计：`_android-sdk` 11626 文件/712MB、`desktop/release3` 350MB（含 79MB 安装包 exe + win-unpacked）、`frontend/android` 74MB、还暂存了 `lostfound.keystore` 签名密钥；真正该入库的只有 167 个文件。.git 已膨胀到 699MB（git add 已写入 blob 对象）。
- HEAD 中 SDK 文件数为 0，说明历史未污染，清理代价低。
- 约定：本地 SDK、Electron 打包产物（release*）、gradle build、*.keystore 一律不入库；提交前先 `git status` 看清单，不要直接 `git add .`。
- 已修复：`git restore --staged` 撤回 `_android-sdk`(11626文件/712MB)、`desktop/release3`(350MB)、`lostfound.keystore`；新建根 `.gitignore`（SDK/`desktop/release*/`/gradle build/`*.keystore`/通用产物）；`git gc --prune=now` 后 `.git` 697MB→**29M**。
- 结果：暂存区 167 文件（源码 35 java + 14 vue + 30 png/docs + 11 md + 配置），HEAD 仍为 d08e9ea 未变，工作区 SDK 与 release3 文件完好。
- 遗留待定：`backend/uploads/downloads/app-release.apk`（5.9MB）仍暂存——属 `/api/file/apk` 分发用的构建产物，是否入库需拍板。
