# 校园失物招领平台 · 项目准备清单（总设计师版）

> 配套文档：《失物招领平台-五人分工方案.md》。本文档回答"开工前要准备什么"：软件环境、IDE 插件、AI 辅助（ZCode/MCP）、前后端依赖、建模与测试工具、云服务账号、风险预置。
> 原则：**最小可用、够用就好**。每项标注【必装】【建议】【可选】；第一周（P1 阶段）全部装完并通过"环境冒烟测试"。

## 〇、明确不准备的东西（防止过度工程）

| 不装/不用 | 原因 |
|---|---|
| Python 环境 | 本项目 AI 能力为零——pHash 是纯 Java 算法，不涉及任何 Python |
| Docker | 5 人组维护镜像成本 > 收益，本机 `java -jar` 直接跑 |
| Redis | 前期不需要；P3 后期做"短时锁定"才引入，到时再装 |
| Milvus/pgvector 向量库 | 本项目没有 RAG，pHash 汉明距离在 MySQL 里就能算 |
| 收费 Navicat 正版 | 用 DBeaver 免费版或 Navicat Premium Lite 替代 |

### 5.2 建议新增的 MCP：MySQL MCP（成员E/C 配置）

让 AI 能直接查表结构、造测试数据、核对查询结果——本项目造 100+ 条带图测试数据时特别省事。

- npm 版：`@benborla29/mcp-server-mysql`（npx 直接跑）；或 Python 版：`pip install mysql-mcp-server`
- 配置示例（标准 MCP JSON，放进 ZCode 的 MCP 配置；具体配置文件位置可在 ZCode 里用 `/zcode-configuration-guide` 技能查询）：

```json
{
  "mcpServers": {
    "mysql": {
      "command": "npx",
      "args": ["-y", "@benborla29/mcp-server-mysql"],
      "env": {
        "MYSQL_HOST": "127.0.0.1",
        "MYSQL_PORT": "3306",
        "MYSQL_USER": "root",
        "MYSQL_PASS": "你的密码",
        "MYSQL_DB": "lost_found"
      }
    }
  }
}
```

> 备选方案：不装 MCP 也行——AI 通过 Bash 直接执行 `mysql -u root -p -e "..."` 效果等价。MCP 的好处是 AI 能"主动看表结构"，更顺手。

### 5.3 AI 使用纪律（写进小组规范）

1. AI 生成的代码，**提交前必须自己能逐行讲清楚**（答辩要求）——讲不清的不许合入 dev。
2. 数据库设计、接口定义这类"设计决策"人来做，AI 只做实现和检查。
3. 文档可让 AI 起草，但需求、UML、实验结论必须自己核（这些是课程评分点）。

## 六、代码依赖清单

### 6.1 后端 Maven 依赖（成员C，按方案 A/JDK17 写）

```xml
<!-- Web + 校验 -->
spring-boot-starter-web / spring-boot-starter-validation
<!-- ORM（比裸 MyBatis 省一半 CRUD） -->
com.baomidou:mybatis-plus-spring-boot3-starter:3.5.7
com.mysql:mysql-connector-j（随 Spring Boot 管理）
<!-- ★ 核心算法库：以图搜图（本项目唯一特殊依赖，走 JitPack） -->
com.github.KilianB:JImageHash:3.0.0
<!-- JWT 登录态 -->
io.jsonwebtoken:jjwt-api / jjwt-impl / jjwt-jackson:0.12.6
<!-- 工具集（图片读入、缩放、字符串处理） -->
cn.hutool:hutool-all:5.8.32
<!-- 接口文档自动生成（Swagger 增强 UI） -->
com.github.xiaoymin:knife4j-openapi3-jakarta-spring-boot-starter:4.5.0
<!-- 实体简化 -->
org.projectlombok:lombok
<!-- 测试 -->
spring-boot-starter-test（含 JUnit 5）
<!-- P3 后期"短时锁定"再引入：spring-boot-starter-data-redis -->
```

**JImageHash 需要在 pom 额外声明 JitPack 仓库**（这是它和普通依赖不同的地方，第一周就要验证能拉下来）：

```xml
<repositories>
  <repository>
    <id>jitpack.io</id>
    <url>https://jitpack.io</url>
  </repository>
</repositories>
```

## 十、风险预置（总设计师提前踩好的坑）

| # | 坑 | 预案 |
|---|---|---|
| 1 | JDK 与 Spring Boot 版本不配套，启动直接报错 | 按第一节配套表二选一，写进 README，全组统一 |
| 2 | JitPack 拉 JImageHash 失败/超时 | 确认 pom 配了 jitpack 仓库；仍失败挂代理或用手机热点（校园网偶发屏蔽） |
| 3 | MySQL 8 时区报错（连接测试就炸） | 连接串加 `serverTimezone=Asia/Shanghai&useSSL=false` |
| 4 | 前后端联调跨域报错 | 后端全局 CorsConfig 第一周写好，禁止靠浏览器插件绕 |
| 5 | 小程序正式版要求备案域名，学生来不及 | 演示走微信开发者工具"真机预览"（开发版），绕开域名要求 |
| 6 | 造的测试数据太少，答辩时"以图搜图"搜不到东西 | 成员E 的初始化脚本预置 100+ 条含图数据（ZCode MySQL MCP 造数很快）；同一物品多角度拍照入库 |
| 7 | 图片存储撑爆仓库/数据库 | 图片存磁盘目录（`/upload/yyyy/MM/uuid.jpg`），库里只存路径 + 64 位哈希；仓库 .gitignore 掉 upload 目录 |
