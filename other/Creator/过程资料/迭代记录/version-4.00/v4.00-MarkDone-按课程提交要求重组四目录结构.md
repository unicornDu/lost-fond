## 六、运行验证与发现的坑（重要）

### 6.1 `mvn spring-boot:run` 在新路径下失效

- **现象**：git-bash 与 cmd 两种环境均报 `错误: 找不到或无法加载主类 com.shiguang.lostfound.LostFoundApplication`（ClassNotFoundException），编译阶段成功。
- **定位**：`java -cp "target/classes" com.shiguang.lostfound.LostFoundApplication` 可正常加载主类（报的是缺 Spring 依赖）→ 类文件与 classes 目录本身没问题，坏在 spring-boot-maven-plugin **fork 子进程组装 classpath** 时对含中文的更深路径（`软件工程\src\web-lostfond\backend`）编码处理出错；旧路径（少一层 `src\`）未触发。
- **绕过（本次采用）**：`mvn clean package -DskipTests`（22s）→ `java -jar target/lost-found-backend.jar`（6.3s 启动）。
- **⚠️ 待办**：《12-部署手册》《运行说明/01-启动步骤》首推命令仍是 `mvn spring-boot:run`——**演示前必须补"新路径请用 jar 方式"提示**（已向用户提出，待拍板后修改）。
