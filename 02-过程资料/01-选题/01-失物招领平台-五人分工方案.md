# 校园失物招领平台（以图搜图）· 五人小组分工方案

> 选题来源：《软件工程课程设计-选题推荐（合并版）》选题 2 —— 基于感知哈希的校园失物招领平台的设计与实现。
> 技术栈：Spring Boot + MySQL + Vue/微信小程序 + JImageHash（纯 Java 感知哈希 pHash）。
> 小组规模：5 人；角色对应课件 6 类岗位，其中"测试及文档"与"数据库及文档"由一人兼任（兼岗说明见下）。
> 填表说明：把"成员A~E"替换成真实姓名+学号后，本文档可直接作为《项目计划书》的分工章节，也可单独交分组名单。

## 二、系统模块 → 负责人映射

| 模块 | 内容 | 主负责人 | 协作 |
|---|---|---|---|
| M1 用户模块 | 注册/登录（JWT）、个人中心、我的发布/我的认领 | 成员C | 前端成员D |
| M2 物品发布模块 | 失物登记/招领登记、图片上传、分类/标签/地点/时间 | 成员C | 前端成员D |
| M3 以图搜图模块（核心亮点） | 入库时计算 pHash 入库；上传照片返回 Top-N 相似物品及相似度百分比 | 成员C | 成员E 出实验数据 |
| M4 检索与筛选模块 | 关键词全文检索、分类/日期/地点筛选、按时间排序 | 成员C | 成员E 建全文索引 |
| M5 认领与消息模块 | 认领申请→发布者审核→认领成功、站内通知、物品状态流转 | 成员C | 成员B 画状态图 |
| M6 管理后台 | 用户管理、信息审核（防虚假/广告）、违规下架、数据统计看板 | 成员D（前端）+ 成员C（接口） | 成员B 出看板原型 |
| M7 数据库 | 全部表结构、索引、初始化数据、备份脚本 | 成员E | 与成员C 对齐字段 |
| M8 前端整体 | 用户端（Vue/小程序）+ 管理后台页面 | 成员D | 按成员B 的 UI 稿实现 |

**物品状态机（M5 的核心，也是状态图素材）**：
`待审核 → 已发布 → (匹配中/无人认领) → 认领申请中 → 已认领`，任意状态可 `已关闭/已下架`。认领需发布者确认，防冒领。

## 三、每人职责细则

### 成员A · 项目经理（兼技术支持）
1. 制定《项目计划书》：WBS 任务分解、甘特图、里程碑（选题提交 / 需求评审 / 设计评审 / 代码冻结 / 验收答辩）。
2. 每周日晚汇总《周报》：本周完成、下周计划、风险与阻塞（例："OpenCV/JImageHash 依赖拉不下来"要提前暴露）。
3. 维护《风险登记表》：至少 5 条风险及应对（人员请假、环境配置失败、进度延期、答辩设备、数据不足）。
4. 技术支持：搭建 Git 仓库（Gitee/GitHub 私有仓库）并制定分支规范（main / dev / feature-*）；负责服务器或本机部署（宝塔/Docker 任选）、录屏环境。
5. 答辩统筹：答辩PPT大纲、主讲分工、预答辩组织（至少演练 1 次）。

### 成员B · 分析和设计及文档（兼美工）
1. 走访 5-10 名同学 + 收集 20 份问卷，整理《需求规格说明书》：功能需求（M1-M6）、非功能需求（相似度匹配响应 < 2s、图片上传 ≤ 5MB、并发 100 人在线）。
2. 画全套 UML 图（用例图、类图、时序图、活动图各至少 1 张，状态图 1 张必画——失物状态机是本项目特色）。
3. 与成员C 共同编写《接口文档》（RESTful：路径、方法、入参、出参 JSON 示例），前端按此并行开发。
4. 美工：用墨刀/Figma 出 UI 设计稿（用户端 6-8 页 + 后台 3-4 页）、统一配色与 Logo，交成员D 实现。

### 成员C · 编码及文档 A（后端 + 核心算法）
1. 搭 Spring Boot 脚手架（三层架构：controller/service/mapper），实现 M1、M2、M4、M5 后端接口。
2. **核心算法（答辩的重头戏）**：集成 JImageHash，物品图片上传后计算 pHash（64 位哈希）存库；"以图搜图"接口 = 计算查询图 pHash → 与库内哈希逐条算汉明距离 → 阈值过滤（建议距离 ≤ 10 起步，实验后定）→ 按相似度降序返回 Top-N。
3. 写《关键算法说明》：pHash 原理（缩放→DCT→取低频→二值化）、为什么抗缩放/水印干扰、阈值如何通过实验确定。
4. 制定《编码规范》（阿里巴巴 Java 规约裁剪版），代码评审后合并 dev 分支。
5. 联调支持：给成员D 提供联调环境与测试账号。

### 成员D · 编码及文档 B（前端）
1. 按成员B 的 UI 稿实现用户端：首页（失物墙/招领墙）、发布页、搜索结果页（以图搜图入口放最显眼位置）、详情页、个人中心。
2. 实现管理后台页面：审核列表、用户管理、统计看板（ECharts：发布量趋势、分类占比、认领成功率）。
3. 先按《接口文档》mock 数据开发，后端就绪后联调；记录《联调问题清单》。
4. 编写《演示视频脚本》（2-3 分钟：丢卡→拍照上传→以图搜图秒匹配→在线认领的完整故事线）。

### 成员E · 测试及文档 + 数据库及文档（兼岗）
1. **数据库侧**：设计 E-R 图与《数据字典》（核心表：user、item、item_image(含 hash_64 字段+索引)、claim_record、message、admin_log）；交付建表 SQL 与初始化数据脚本（预置 100+ 条含图片的测试物品数据，保证以图搜图演示不冷场）；制定备份方案（mysqldump 定时脚本）。
2. **测试侧**：编写《测试计划》与《测试用例表》（功能用例 ≥ 40 条，覆盖状态机每条迁移路径）；用 Postman 做接口测试，维护《缺陷跟踪表》（编号/描述/严重级/状态/修复人）。
3. **亮点实验（强烈建议做）**：《以图搜图准确率实验报告》——同一物品拍不同角度/光照/距离的照片各 5 张，统计 pHash 命中率；对比 aHash / dHash / pHash 三种哈希的召回表现，给出最终算法与阈值选择依据。这一个实验就能撑起报告的"实验与分析"章节。
4. 可选加分：JMeter 模拟 50 并发上传搜图，记录平均响应时间。

## 六、协作规范

1. **Git**：main（可发布）/ dev（日常集成）/ feature-xxx（个人开发）；提交信息格式 `模块: 做了什么`；合并 dev 前必须由另一名编码成员看过代码。
2. **文档**：统一放仓库 `/docs` 目录，命名 `编号-文档名-版本`（如 `03-需求规格说明书-v1.0.docx`）；改动走"谁负责谁改，改完群里说一声"。
3. **会议**：每周一次例会（15 分钟，对照周报过进度）；代码联调期改为每两天一次站会（可线上）。
4. **风险上报**：任何人卡住超过半天，直接群里喊成员A，不许自己闷头耗——分工不等于各干各的。
