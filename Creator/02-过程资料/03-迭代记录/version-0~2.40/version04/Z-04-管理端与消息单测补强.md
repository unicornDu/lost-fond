## 现象与证据

`backend/src/test` 现有 7 个测试类 35 用例（PHash×5、Auth×8、Claim×9、Search×5、FileStorage×5、Item×2、HashExperiment 默认 skip）。以下服务**完全没有单测**：

| 服务 | 未覆盖方法 | 风险 |
|---|---|---|
| `AdminService` | listUsers / setUserStatus / listItems / auditItem / offlineItem / deleteItem / listLogs / regenThumbs / dbCounts（9 个公开方法） | 审核状态机（B-03 守卫）、删除连带清理（B-05）、封禁边界（不可封管理员）全靠 test_api.py 黑盒兜底，重构即裸奔 |
| `StatsService` | homeStats / categoryRatio / dashboard | B-02 口径修复无回归锚点 |
| `MessageService` | list / unreadCount / markAllRead / markRead | markRead 越权守卫（非本人 404）无回归 |

## 修复要求

1. 新增 `AdminServiceTest`（Mockito，风格随 `ClaimServiceTest`），至少覆盖：
   - `auditItem`：通过/驳回两分支；B-03 守卫（已完成启事再审核拒绝）；驳回后重新通过恢复可见状态；
   - `deleteItem`：按 `ref_id=itemId` 全清 message（B-05 口径）、清理 claim/images 并调用 FileStorage 删盘；
   - `setUserStatus`：不可封管理员；封禁写 admin_log；
   - `listItems` 的 auditStatus 过滤、`dbCounts` 六表计数。
2. 新增 `MessageServiceTest`：list 按 userId 范围 + LIMIT 50；unreadCount 只数 is_read=0；markAllRead 只更新未读；markRead 非本人 404 / 本人成功。
3. `ItemServiceTest` 补 `detail` 可见性用例（修正 E：B-01 是 P0 修复，目前只有 test_api.py 黑盒兜底，零单测锚点；mock `ItemMapper`/`ItemImageMapper`/`UserMapper` + 通过 `UserContext.set(...)` 控制身份）：

   | 场景 | 期望 |
   |---|---|
   | 匿名 + 待审启事（auditStatus=0） | `BusinessException(404)` |
   | 本人 + 待审启事 | 200，返回 VO |
   | 管理员 + 待审启事 | 200，返回 VO |
   | 匿名 + 已过审启事 | 200 |
   | 匿名 + 已下架启事 | `BusinessException(404)` |

4. `StatsService` 用例可并入 AdminServiceTest 或独立（homeStats/dashboard 的 audit=1 口径）。
5. 建议规模 ≥15 用例（不含本条 detail 的 5 例与 Z-10/Z-07 文件并入的用例，合计预计更多），`mvn -o -B test` 全绿（预计 35 → ≥55）。
6. **文档同步（05 B 组口径，勿漏）**：Creator/01-交付文档/08 单元测试行的类数/用例数逐行更新并修正文末总数；Creator/01-交付文档/10 单测行 35 → 实际值；Creator/01-交付文档/09 若过程中发现新缺陷按 #24 起登记。
