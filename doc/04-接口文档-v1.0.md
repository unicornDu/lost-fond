# 校园失物招领平台 · 接口文档 v1.0

> 交付物编号 04（杜林峰 + 张家豪）。RESTful，BaseURL = `http://localhost:8080`（前端经 Vite 代理 `/api`、`/uploads`）。全量 **51 个端点**（v2.20 增守望 5 个、v2.41.1 增每日统计 1 个）。
> 统一响应包装：`{ "code": 200, "msg": "success", "data": ... }`；code≠200 为失败（401 未登录 / 403 无权限 / 404 不存在 / 413 图片过大）。
> 鉴权：请求头 `Authorization: Bearer <token>`（登录/注册返回 token）。标注 🔒 的接口必须登录；🛡️ 需管理员。

## 三、以图搜图 M3（核心）

| 方法 | 路径 | 说明 | 入参 | 出参 data |
|---|---|---|---|---|
| POST | /api/search/image | 上传图片返回 Top-N | multipart `file`；可选 query `threshold`、`topN`（03 T-02：评测覆盖用，不传用 application.yml 配置；修复 Z-08：`image-search.allow-override=false`（prod）时忽略入参，开启时入参 clamp 到 `topN∈[1,50]`、`threshold∈[0,64]`，越界不报 400） | `ItemVO[]`（按 similarity 降序，含 similarity 百分比） |
| GET | /api/search/indexed-count | 已建 pHash 索引的图片数 + 生效参数 | — | `{count, threshold, topN}`（03 T-03：前端文案同步阈值用） |
| POST | /api/search/reindex | 为漏算 pHash 的图补算 | — | `{reindexed,total}` |
| POST | /api/search/match-report | 🔒 生成匹配报告 PDF（P2：以图搜图结果固化为可带走的交付物） | multipart `file`（同 /image 的 clamp 口径） | `{deliveryId,title,hits}`（PDF 经交付体系下载/打开） |

算法：查询图 → JImageHash `PerceptiveHash(64)` → 64 位指纹 → SQL `BIT_COUNT(phash ^ q)` 求汉明距离 → `≤12` 阈值过滤 → 按启事取最小距离升序 Top-10（03 T-02 标定，旧值 10/6）→ 相似度 = `(1 - dist/64)×100`。

## 六、守望订阅 M7（v2.20 新增，🔒 全部需登录）

| 方法 | 路径 | 说明 | 入参 | 出参 data |
|---|---|---|---|---|
| GET | /api/watch/plans | 方案目录（数值权益，前端按 code 走 i18n） | — | `WatchPlanVO[]`：`{code,name,price,termPrice,quota,threshold,retentionDays,popular}` |
| GET | /api/watch/me | 总览：当前订阅 + 已用守望位 + 守望位列表（顺带惰性清理过期守望位、补建免费订阅） | — | `WatchOverviewVO`：`{plan, quota, used, targets[]}` |
| POST | /api/watch/subscribe | 开通 / 切换方案（课程演示只落库权益，不扣费） | `{planCode: light\|steady\|crowd, cycle: month\|semester}` | `WatchSubscriptionVO`（降档时超额守望位自动结束） |
| POST | /api/watch/targets | 上传守望照片 → 服务端算 pHash 占一个守望位（multipart） | 表单 `file`（必填，同上传口径校验）+ `label?`（≤60 字）+ `sourceItemId?`（从详情页开启时记录） | `WatchTargetVO`：`{id,label,imgUrl,hitCount,lastHitItemId,lastHitTitle,createTime,expireTime,remainingDays}`。配额满 → 400 `守望位已满（当前方案 N 个）` |
| DELETE | /api/watch/targets/{id} | 结束守望（只置 status=0 保留历史行；缩略图事务提交后清理） | — | null（他人守望位 → 404） |

**联动行为**：管理员审核通过一条**招领**（found）启事时，`WatchService.matchOnApprove(item)` 反查全部生效守望位（排除启事发布者本人与已过期），最小汉明距离 ≤ 守望人方案阈值（轻守 10 / 长守 12 / 众守 14）即写 `type=watch` 站内通知（含相似度百分比，refId=启事ID），并累加 `hitCount`、记录 `lastHitItemId`。对应《01-SRS》FR-7。

## 七、错误码约定
| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数/业务校验失败（msg 为具体提示） |
| 401 | 未登录或令牌失效 |
| 403 | 无权限（非本人/非管理员） |
| 40301 | 账号已被封禁（E-05：仅 `/api/auth/me` 对持有效令牌的封禁用户返回，HTTP 403） |
| 404 | 资源不存在；**待审核/已下架/已关闭启事对非本人非管理员也返回 404**（修复 B-01 可见性规则，不用 403 防探测） |
| 405 | 请求方法不被支持（修复 B-06 新增） |
| 413 | 上传超限 |
| 500 | 服务器异常 |

> 修复 B-06：错误响应的 **HTTP 状态码与 body.code 一致**（400→400、401→401、403→403、404→404、405→405、413→413、500→500）；未知路径与方法不匹配不再落进 500 兜底。前端 axios 错误分支读 `err.response.data.msg`、401 用 `body.code===401 || status===401` 双条件，已确认兼容。
