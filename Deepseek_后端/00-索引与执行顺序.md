## 二、🚨 环境红线（不遵守会直接编译失败）

本机持久环境变量 `JAVA_HOME = D:\Visual_Stdio_Code\Java_peizhi\JDK`，指向的是 **JDK 25**，**不是** JDK 21。

- JDK 25 下 Lombok 不生成 getter/setter，`mvn compile` 会报一堆 `找不到符号: 方法 getStatus()` 之类，看起来像代码 bug，实际是 JDK 不匹配。
- **任何 Maven 命令前必须先设置**：

```powershell
$env:JAVA_HOME='D:\Visual_Stdio_Code\Java_peizhi\JDK21'
```

- 已验证的正确命令（在 `lost-found/backend` 目录下执行）：

```powershell
$env:JAVA_HOME='D:\Visual_Stdio_Code\Java_peizhi\JDK21'
& 'D:\Visual_Stdio_Code\Maven\apache-maven-3.9.16\bin\mvn.cmd' -o -B -DskipTests package
& 'D:\Visual_Stdio_Code\Maven\apache-maven-3.9.16\bin\mvn.cmd' -o -B test '-Dtest=PHashUtilTest,AuthServiceTest'
```

> 注意：`HashExperimentTest` 会**覆盖仓库里已提交的** `backend/scripts/exp_results.csv`、`exp_per_transform.csv`，除非任务要求，不要跑它。

## 五、全局约束（每个 Prompt 都适用）

1. **不要改** `backend/uploads/seed/`、`_src/`、`_query/`、`_exp/` 下的图片与 `manifest.json`（它们是演示与实验基准，且已提交 git）。
2. **不要改** `backend/scripts/exp_results.csv`、`exp_per_transform.csv`（实验原始数据，已核对可复现）。
3. 修改数据库结构时，`schema.sql`（文档口径）与**实际库**都要改，且保证三方一致（见 `05` 的 `idx_phash` 问题）。
4. 代码注释保持现有风格：中文、说明"为什么这么改"。
5. **不要引入新的重型依赖**（不要引入 Spring Security 全链路、Redis、Elasticsearch、向量库）。项目定位是课程设计，单机部署。
6. 每完成一条修改，必须给出**可复现的验证证据**（命令 + 实际输出），不接受"应该可以"。
7. 保持接口响应的 `{code,msg,data}` 结构不变（前端 axios 拦截器依赖它）。
8. 涉及前端或接口字段变化时，同步更新 `lost-found/docs/04-接口文档-v1.0.md`。
