## 5. JWT 登录态全链路（★★★ 必背）

```
① 登录成功 → JwtUtil.generate(userId, account, role) 签发 token（sub=userId, role, 过期时间, HMAC 签名）
② 前端存 localStorage['shiguang_token']
③ 每次请求 axios 拦截器加头 Authorization: Bearer <token>
④ JwtInterceptor.preHandle：读头 → jwtUtil.parse 验签 → 查库校验用户 → UserContext.set(uid, role)
⑤ Service 用 UserContext.requireUserId()（未登录 401）/ requireAdmin()（非管理员 403）
⑥ afterCompletion：UserContext.clear()
```

代码：`util/JwtUtil.java`、`interceptor/JwtInterceptor.java`、`context/UserContext.java`

### 5.1 三个设计细节（能答出来说明真读过代码）

1. **`OPTIONS` 请求直接放行** —— 跨域预检不带 token，拦了会 401。
2. **带 token 也查一次库**（`userMapper.selectById`）—— 封禁（`status=0`）或用户已删除时**等同匿名**，实现"封禁/删除实时生效"，不用等 token 过期。
3. **`afterCompletion` 必须清 ThreadLocal** —— Tomcat 线程复用，不清会导致下一个请求"继承"上一个用户的身份（串号）。

### 5.2 为什么用 JWT 不用 Session

| 维度 | JWT | Session |
|---|---|---|
| 状态 | **无状态**，服务端不存 | 服务端存 session |
| 扩展 | 加机器不用同步 session | 需要粘性/共享存储 |
| 跨端 | 一个请求头即可，无 Cookie 依赖 | — |

### 5.3 JWT 的局限（主动说出来加分）

- **无法主动注销**：登出只是前端删 token，旧 token 在有效期内仍可用 → 本项目用"每次请求查库校验 status"来兜（代价是每请求一次库查询）。
- **payload 可解码不可篡改**：所以**不要把敏感信息塞进 token**，我们只放 uid / role。
- **限流/黑名单需要额外存储**：真要立刻失效，得引入 Redis 黑名单。

## 9. MyBatis-Plus 与 SQL 安全（★常问）

- [ ] `BaseMapper<T>` 自带 `selectById / selectList / selectPage / insert / updateById / deleteById`
- [ ] `QueryWrapper` 常用：`.eq() .like() .in() .isNull() .orderByDesc()`
- [ ] 分页：`selectPage(new Page<>(page,size), wrapper)`，需 `MybatisPlusConfig` 注册**分页插件**（不注册则不分页）
- [ ] 字段映射：`map-underscore-to-camel-case: true` → `create_time` ↔ `createTime`
- [ ] 复杂 SQL 用 `@Select` 注解（如 `ItemImageMapper.searchByHash`）
- [ ] **防 SQL 注入**：`#{}` 是预编译占位符（传值，安全）；`${}` 是字符串拼接（**可注入**，禁止用于用户输入）

**追问**："`LIKE` 会不会注入？" → 用 `#{}` 传参不会；但如果自己拼 `'%'+k+'%'` 再走 `${}` 就会。本项目的 `like("title", k)` 是参数化的。

## 11. 文件上传安全（★本项目做得比较细）

`service/FileStorageService.java`

| 关卡 | 做法 |
|---|---|
| ① 扩展名白名单 | `ALLOWED = {jpg, jpeg, png, gif, bmp, webp}` |
| ② **文件头魔数校验** | `jpg/jpeg: FF D8 FF`、`png: 89 50 4E 47`；`webp` 单独校验 `RIFF....WEBP` |
| ③ 大小限制 | `application.yml` 5MB + 前端上传前拦一道 |
| ④ 重命名 | UUID 文件名，杜绝"原名覆盖 / 原名带路径" |
| ⑤ 落盘路径 | `uploads/yyyy/MM/uuid.jpg`，按年月分目录避免单目录文件过多 |
| ⑥ 安全性 | 只存到固定根目录下，路径拼接后校验不越界（防目录穿越） |
| ⑦ 缩略图 | 生成 480px 宽 `_thumb`，列表页用小图 |

**为什么要魔数校验**：只看扩展名会被"把 a.exe 改名成 a.jpg"骗过；读文件头几个字节才能确认真是图片（缺陷 #? · 审查 2.16 引入）。

- [ ] 能说出"扩展名 + 魔数"双校验的必要性
- [ ] 能说出为什么要 UUID 重命名（消除用户可控文件名带来的风险）
