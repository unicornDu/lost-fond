  3. 结论回填到 `application.yml` 的阈值与报告"实验与分析"章节。
- 【验收】docs/ 新增 11-以图搜图准确率实验报告（含数据表和图）；阈值有实验出处。

## 二、代码层面问题（P0 两项，P1 若干）

### 2.1 建 git 仓库（P0，半小时，防翻车）
- 【现状】项目无版本控制，误删无法回退；"Git 分支规范"本身是项目经理交付物。
- 【做法】`web-lostfond/` 下 `git init`，创建 `.gitignore`（内容见附录 A），首次提交后建 main/dev 分支规范。
- 【验收】`git log` 有初始提交；`node_modules/target/dist/uploads 运行时图片/_*.log` 不入仓。

### 2.2 敏感信息外置（P0，建仓前必须做，否则进 git 历史）
- 【现状】`application.yml` 中 JWT secret 硬编码（注释自带 please-change-in-prod）、MySQL root/123456 明文。
- 【做法】新建 `application-local.yml`（gitignore）放真实密码与 secret，`application.yml` 留占位符 `${DB_PASSWORD:123456}` / `${JWT_SECRET:dev-only}`；README 写明本地启动方式。
- 【验收】仓库中 grep 不到真实密码与完整 secret。

### 2.3 管理后台前端页面（P0，功能最明显的洞）
- 【现状】`AdminController` 六组接口全部就绪且 `UserContext.requireAdmin()` 鉴权完整（已抽查 8 个端点），但前端**零页面**：无 `/admin` 路由、NavBar 无入口。
- 【做法】成员D 用 v3-admin-vite 风格新增管理端（可做成 `/admin` 独立布局）：
  - 数据看板（`GET /api/admin/stats` + ECharts：用户/启事趋势、分类占比、认领成功率）；
  - 启事审核列表（`GET /api/admin/items` + `POST /api/items/{id}/audit`）；
  - 下架/删除（offline/delete）、用户管理（`GET /api/admin/users` + status）；
  - 路由守卫加角色校验：`stores/user.js` 已有 `isAdmin` getter，`meta: { roles: ['admin'] }`。
- 【验收】管理员登录可见入口，审核/下架/看板全流程可演示；非管理员访问 /admin 被拒。

### 2.4 管理员提权流程（P1）
- 【现状】提权靠手工 SQL（README 与 test_api.py 末尾均提示 `UPDATE user SET role=1`），演示易卡壳。
- 【做法】方案任选：① 注册时若账号在 `admin_whitelist` 配置名单中自动 role=1；② DataInitializer 播种的演示管理员（10000001）在 README 高亮为唯一演示入口；③ 后台"用户管理"支持管理员互相提权。
- 【验收】演示脚本里不再出现手工 SQL。

### 2.5 前端 401 处理不闭环（P1，十行代码）
- 【现状】`api/index.js` 响应拦截器收到 401 清 localStorage，但不跳转，用户停在当前页看报错。
- 【做法】两处 clearSession() 后追加：`if (location.pathname !== '/auth') location.href = '/auth?redirect=' + encodeURIComponent(location.pathname + location.search)`。
- 【验收】token 过期后任意操作 → 自动回登录页，登录后回原页。

### 2.6 后端零单元测试（P1，低成本加分）
- 【现状】pom 引入 spring-boot-starter-test 但 `src/test` 目录不存在。
- 【做法】补 JUnit 5 用例：`PHashUtil`（同图哈希一致、变体图距离 < 阈值、不同图距离 > 阈值）、`SearchService.similarityFromDist`（边界 0/64）、`AuthService`（重复学号注册、错误密码）。`mvn test` 进报告。

### 2.7 上传安全：仅校验扩展名（P1，报告"上线前必改"条目）
- 【现状】`FileStorageService.ALLOWED` 只查扩展名（gif/bmp/webp 均放行），文件内容不校验即落盘并被 `/uploads/**` 输出。
- 【做法】读文件头魔数校验（JPEG: FF D8 FF，PNG: 89 50 4E 47，GIF: GIF8，WEBP: RIFF....WEBP）；更彻底的方案：用 Hutool `ImgUtil` 二次编码后再落盘（顺带解决 2.8）。报告里写明当前取舍。
- 【验收】改名为 .jpg 的文本文件被拒绝。

### 2.8 列表页直接用原图当封面（P1，体验/流量优化）
- 【现状】uploads 已 2.8M（仅演示数据）；卡片封面 4:3 约 300px 宽却加载原图。
- 【做法】落盘时同步生成缩略图（Hutool ImgUtil.scale，宽 480），`ItemVO` 增加 `thumbUrl`，`ItemCard`/列表用 thumbUrl、详情用原图；历史数据用 `reindex` 思路补一个 `POST /api/admin/regen-thumbs`。
- 【验收】列表页网络面板可见图片体积明显下降。

### 2.9 关键词检索：文档与实现不一致（P1）
- 【现状】schema.sql 建了 ngram 全文索引，但 `ItemService` 第 108 行实际用 `like("title", k).or().like("description", k)`，全表扫、用不上该索引。
- 【做法】二选一：① 改 `MATCH(title,description) AGAINST(? IN BOOLEAN MODE)`（MyBatis 注解 SQL，需 MyISAM/MySQL8 ngram 支持，注意 MyBatis-Plus QueryWrapper 不支持全文语法要手写 SQL）；② 保留 LIKE 并在文档中删去全文索引或注明"数据量小，LIKE 足够"。**不要留着"文档说了但代码没做"的状态。**
- 【验收】实现与 06-数据库设计文档一致。

### 2.10 以图搜图性能演进说明（P2，写报告即可，不必实现）
- 【现状】`BIT_COUNT(phash ^ q)` 全表扫，44 张毫秒级，万级也可接受。
- 【做法】报告性能章节写清当前复杂度与演进方案：64 位指纹分 4 段建前缀索引缩小候选集（参考 `Github/JImageHash`、`Github/314loveshiwu` 思路）、或迁移专门向量索引。当前规模不实现是合理取舍，写明即可。

### 2.11 CORS 与部署注意（P2）
- 【现状】`CorsConfig` 为 `allowedOriginPattern("*") + allowCredentials(true)` 全放行；前端走 Vite 代理实际不受影响。
- 【做法】保留（课内演示便利），在部署手册与报告"安全设计"一节写明：上线应收紧为具体域名、JWT secret 更换、数据库独立账号最小权限。

  localStorage.removeItem('shiguang_token')
