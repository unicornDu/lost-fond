## 二、执行顺序建议

**E-01**（账号地基，E-04/E-05 都依赖 user 资料）→ **E-02**（审核闭环）→ **E-03**（私信）→ **E-06**（纯前端，可随时穿插）→ **E-05** → **E-04** → E-07 → E-08（可选项，答辩前有余力再做）。

E-01/E-02/E-03 都会触碰 `scripts/test_api.py` 的**幂等基线**，务必逐条处理（见红线 4），不要攒到最后一起改。

## 三、公共红线（每条执行时同样遵守，各文件文末亦有副本）

1. `JAVA_HOME` 指 JDK21；**中文路径下禁止 `mvn spring-boot:run`**（argfile 编码假错），启动验证一律 `mvn -o -B -DskipTests package` + `java -jar target/lost-found-backend.jar`。
2. `scripts/exp_*.csv`、`docs/11` 数据表零修改（D-01 延续）。
3. 所有文档数字改动必须与实测输出一致（宁可改小），逐行统计口径见 docs/08 文末说明。
4. **幂等基线联动（E 批特有）**：`test_api.py` 现有基线为"跑后 item=60 / item_image=120 / message 回基线；admin_log 只增不计入"。E-02（审核通知）、E-03（私信回复）都会**新增 message 写入**，跑完脚本 message 不再自然回基线——执行方必须二选一并记录在修复记录里：① 把新增通知计入新基线（更新断言数字并注明原因）；② 断言结束后清理本批新增消息。**禁止直接删掉 message 回基线断言了事。**
5. 新增/变更接口必须同步 `docs/04-接口文档`；新增字段/表必须同步 `docs/06-数据字典`；改变 FR 口径的（E-01 资料编辑、E-03 私信双向）必须同步 `docs/01-SRS` 对应条目。文档先行或同步改，不许只改代码。
6. 不新增任何 `_*.txt`/`_*.json` 调试残留入库；git 提交由组员执行。
7. **验证方式必须能证伪**：新增端点的验收 = 正向 + 鉴权负向 + 参数边界三类断言；"资料编辑"类修复必须先改值、再读回、确认不一致才算通过。
8. 每条修完在 `Prompt/修改建议_prompt/version_05/99-修复记录.md` 追加对应小节（逐条修改+证据），格式沿用 version_02 的 01~06 修复记录。

## 四、不列入本批的已知取舍（答辩时可口径统一为"展望"）

以下各项**是有意取舍或算法/规模边界，不是缺陷**，测试报告 docs/10 §4 已声明，本批不做：

| 项 | 现状 | 展望口径 |
|---|---|---|
| pHash 对旋转/大裁剪失效 | 报告 11 已量化（旋转10°/裁剪70% 召回≈0） | 多图入库+拍摄引导，后续可上特征点匹配（SIFT/ORB）|
| JWT 无刷新/无服务端吊销 | 无状态换扩展性；封禁实时性靠拦截器查库 | 后续 refresh token 或 Redis 黑名单 |
| 限流/浏览去重/缩略图缓存为内存态 | 重启丢失、不支持多实例 | 后续 Redis 化 |
| 关键词 LIKE 无全文索引 | schema.sql 已声明数据量大了再评估 | MySQL ngram 全文索引或 ES |
| 消息 30s 轮询非推送 | 可用性已达标 | WebSocket |
| 图片无水印/防盗链 | UUID 路径弱防护（E-08 可选做防盗链） | Nginx 层处理 |
