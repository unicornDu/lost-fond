## 一、形态说明

桌面端 = **Electron 壳 + 既有 Vue 前端（dist 构建产物）+ 本机 Spring Boot 后端**：

```
ShiGuang.exe（Electron 壳，纯展示容器，不含业务数据）
   └── renderer/  ← frontend 的构建产物（base=./，hash 路由）
                      └── axios/图片 → 绝对地址访问 apiBase（默认 http://localhost:8080）
ShiGuang.exe 不内嵌后端；后端 java -jar 照旧独立运行（壳可选拉起，见下）
```

与 Web 模式共用同一套源码：差异只有三处运行时适配（Web 行为零变化）——

| 适配点 | 文件 | 说明 |
|---|---|---|
| hash 路由 | `frontend/src/router/index.js` | file:// 下 history 模式无法工作，桌面自动切 hash |
| API/图片绝对地址 | `frontend/src/utils/desktop.js` + 各 `:src` 绑定 | file:// 无同源，`/uploads/**` 与 API 转绝对地址 |
| 桌面专用构建 | `frontend/vite.desktop.config.js` | base=./ + 禁用 manualChunks（element-plus 拆 chunk 在 file:// 下触发循环依赖） |

## 二、目录与文件

```
desktop/
├── main.cjs              # 主进程：窗口/健康检查/单实例锁/深链接/外链守卫
├── preload.cjs           # contextBridge 白名单：只读配置 + 深链接事件（无 Node 能力下放）
├── prepare-renderer.js   # 打包前置：vite 桌面配置构建 → renderer/
├── package.json          # electron + electron-builder；build 段 = NSIS per-user
├── renderer/             # 构建产物（gitignore）
└── release2/             # 安装包输出（gitignore）：ShiGuang Setup 1.0.1.exe
```

## 三、日常运行

### 方式 A：开发模式（改前端代码实时热更）

```bash
# 三个终端：
cd backend  && java -jar target/lost-found-backend.jar        # 或 --server.port=8081
cd frontend && BACKEND_PORT=8081 npm run dev                  # 8080 可用时不加前缀
cd desktop  && ELECTRON_RENDERER_URL=http://localhost:5173 npm run dev
```

开发模式 API 走 Vite 代理，壳不做健康检查拦截。

### 方式 B：打包安装（演示/分发）

```bash
cd desktop && npm run dist        # = 构建 renderer + electron-builder
# 产物：desktop/release2/ShiGuang Setup 1.0.1.exe（NSIS，per-user 免管理员，可选安装目录）
```

安装后双击桌面快捷方式「拾光失物招领」：

1. 壳先探活 `<apiBase>/api/stats`（2.5s 超时）；
2. 后端未启动 → 弹窗提示启动方法（此时点"仍然打开"只见错误提示，属预期）；
3. 后端正常 → 直接进应用。**数据与程序分离**：壳的可执行目录永远不写。

### 让壳自动拉起后端（可选，"双击即用"）

编辑 `%APPDATA%/shiguang-desktop/config.json`（菜单栏无入口，手动建文件即可）：

```json
{ "apiBase": "http://localhost:8080",
  "backendJar": "D:/Visual_Stdio_Code/Dai_ma/软件工程/web-lostfond/backend/target/lost-found-backend.jar" }
```

配了 `backendJar` 且探活失败时，壳自动 `java -jar` 拉起后端（最多等 40s），壳退出时随之上杀，不留孤儿进程。**MySQL 仍需已在本机运行。**

也支持环境变量 `SHIGUANG_API_BASE` / `SHIGUANG_BACKEND_JAR`。
配置优先级（P3 发行机制，高→低）：**userData/config.json（用户手改）> 环境变量 > 包内 `default-config.json`（发行时烙入）> localhost:8080**。

## 三·A 局域网分发（别人电脑装上连你的后端，数据同步）

后端只跑在你一台机器上，大家连同一个库——发布/认领/消息实时互通。

**你这一侧（服务端，每次开机做一次）：**
1. 启动后端：`cd backend && java -jar target/lost-found-backend.jar`（MySQL 需已启动）；
2. 防火墙放行 8080：首次启动 Java 弹窗点"允许"；或 手动：控制面板→防火墙→高级设置→入站规则→新建→端口 8080/TCP 允许；
3. 查本机局域网 IP：`ipconfig` → IPv4（本机当前为 `10.140.76.101`，校园网 DHCP 可能变化，分发前确认）。

**别人那一侧（两种方式二选一）：**
- **方式 a（免重打包）**：正常安装后，建 `%APPDATA%\shiguang-desktop\config.json` 写 `{"apiBase": "http://10.140.76.101:8080"}`；
- **方式 b（零配置发行包，推荐发同学）**：把 `desktop/default-config.json` 的 `apiBase` 改成 `http://10.140.76.101:8080` → `cd desktop && npm run dist`——产出的 Setup.exe 装上即连，无需任何配置。

> 注意：桌面端连远程后端时，交付文件卡片自动降级为"下载到本机"（原生打开仅在壳与后端同机时可用，已做降级兜底）。

## 四、桌面特性（答辩可讲）

| 特性 | 实现 | 出处 |
|---|---|---|
| 单实例锁 | `requestSingleInstanceLock`，二次启动唤起已有窗口 | ZCode 文档 §1.4 |
| **交付文件原生打开（P2）** | 服务端 `/api/file/open` 按 deliveryId 读回路径 → 壳 IPC `shell.openPath`/`showItemInFolder`；壳侧 realpath+uploads 段+backendDir 三重校验（dsh present.open 的 open/reveal 转译） | dsh 文档 §1.4 |
| **托盘驻留（P2）** | 关窗隐藏到托盘，菜单"退出"真退出（随杀自动拉起的 jar） | ZCode 文档 §2.3 裁剪 |
| **窗口状态记忆（P2）** | 位置/尺寸持久化 `userData/window-state.json`（自写约 20 行） | ZCode 文档 §3.2 裁剪 |
| 深链接 | `lostfound://item/<id>` 注册协议，拉起应用直达启事详情；官网/分享页可一键唤起 | ZCode 文档 §1.3（zcode://workspace/open 思路） |
| 外链守卫 | `setWindowOpenHandler` + `will-navigate`：http(s) 外链一律交系统浏览器，壳内只跑本应用 | 安全设计 |
| 安全基线 | `contextIsolation:true`、`nodeIntegration:false`，preload 只暴露只读配置与一个事件订阅 | ZCode 文档 §2.2 |
| 后端探活 | 启动前 health check + 友好弹窗；可选自动拉起并随壳退出 | dsh"本地服务"思路 |
| 明确不做 | 自更新（electron-updater/blockmap）、托盘常驻、多窗口——课程体量的既定取舍，答辩口径"了解工业级方案，避免过度工程" | 落地流程文档 §0/§5 |

## 五、环境备忘（本机踩过的坑）

1. **8080 被出站连接随机占用**：本机 TCP 动态端口范围从 1024 起（默认应为 49152），ZCode 等程序的长连接会把 8080 占为源端口，后端绑定失败。管理员执行一次后恢复默认：
   `netsh int ipv4 set dynamicport tcp start=49152 num=16384`（重启生效）。
   未修复前的替代：后端 `--server.port=8081` + 前端 `BACKEND_PORT=8081` + 桌面 `SHIGUANG_API_BASE=http://localhost:8081`。
2. **Electron 下载失败**：`npm install` 需镜像环境变量
   `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`；
   electron-builder 首次构建下载 winCodeSign 时，压缩包内 macOS 符号链接在非管理员 Windows 解压报
   "客户端没有所需的特权"——已手动解压至 `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\winCodeSign-2.6.0` 绕过（windows/darwin 无关紧要的部分报错不影响）。
3. **release 目录被锁**：曾在打包产物目录里直接跑过 exe 后目录被句柄占用无法删除（疑似杀软扫描），
   输出目录已改为 `release2`；旧 `release/` 重启后可删。
   2026-10-17 又出现 `release2\win-unpacked\resources\app.asar` 被句柄占用（无进程，疑似 Defender 扫描）导致
   `electron-builder` 报 `ERR_ELECTRON_BUILDER_CANNOT_EXECUTE`。绕过办法：
   `npx electron-builder -c.directories.output=release3`，产物 `release3/ShiGuang Setup 1.0.1.exe`（已复制回 release2）。
4. **应用图标**：`desktop/build/icon.ico`（橙渐变圆角 + 「拾」，与 Web favicon 同款设计，PIL 生成，含 16~256 多尺寸）。换图标时替换该文件重打包即可；electron-builder 约定即 `build/icon.ico`。
