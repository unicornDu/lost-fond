## 二、以图搜图 / pHash 算法（学核心模块实现）

| 仓库 | Star | 语言 | 参考什么 |
|---|---|---|---|
| KilianB/JImageHash | 443 | Java | **本项目核心依赖**。官方库，README 有用法示例 |
| KilianB/JImageHash-Examples | 7 | Java | 官方示例代码，直接看怎么调 aHash/dHash/pHash、怎么算汉明距离 |
| ldqk/ImageSearch | 1360 | C# | 本地千万级图库"以图搜图"完整 Demo（分块哈希 + 索引加速），语言不同但**算法思想和工程思路完全可搬**，作者的博客文章也值得读 |
| soulteary/simple-image-search-engine | 157 | Python | 三步构建图片搜索引擎，理解"特征提取→索引→检索"流程 |
| chn-lee-yumi/MaterialSearch | 1968 | Python | 语义搜索本地照片的产品形态参考（搜图交互怎么做） |
| ccloli/Search-By-Image | 130 | JS | 浏览器以图搜图工具，看产品交互 |

> 工程要点（对应清单里的风险 7）：图片多以后，逐条算汉明距离会慢，参考 ImageSearch 的思路做"分段哈希 + 前缀索引"，1000 张图内其实 MySQL 全表扫也够——报告里把这段权衡写清楚就是加分点。

## 四、建议的"抄法"路线图

1. **第 1 周**：clone WarmSearch 四个仓库跑通 → 照它的表结构画出你们自己的 E-R 图（加 `item_image` 表存 pHash 字段）→ 看懂它的登录/发布/认领接口划分。
2. **第 2 周**：成员C 跑 JImageHash-Examples 的示例，实现"上传图片 → 计算 pHash → 汉明距离 Top-N"最小模块。
3. **前端并行**：成员D 拷 v3-admin-vite 做管理后台骨架；用户前台参考 WarmSearch-PC 的页面结构用自己的代码实现（别整目录复制）。
4. **答辩差异化**：WarmSearch 等所有同类项目都没有以图搜图、没有准确率实验——这两点是你们报告和答辩的核心卖点，参考项目负责"不掉分"，pHash 模块负责"拿高分"。
