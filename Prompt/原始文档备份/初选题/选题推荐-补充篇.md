# 软件工程课程设计 · 选题推荐（补充篇）

> 定位：配合已有的 `选题推荐.md`（纯 Java 向 8 个选题）使用，本篇**新增 12 个选题**。
> 本篇重点：把你们学过的 **C / C++** 用起来，并给出"看起来像课设、实际上有硬核内核"的方向，避开全年级撞题。
> 已知技能：C、C++、数据库（MySQL）、Java、JavaWeb
> 小组规模：4–5 人（项目经理 / 分析设计及文档 / 编码及文档 / 测试及文档 / 数据库及文档 / 其它角色）

---

## 零、先说结论：老师给的清单有 3 个坑

| 原题 | 问题 |
|---|---|
| 基于 iOS 的电商 APP / 动漫播放器 / 视频展示系统 | 需要 macOS + Xcode + Swift/OC，你们没学过，4–5 人做不完，环境就能卡掉一半人 |
| 基于 C# 的建材类仓储账务一体化系统 | 需要 .NET / C#，技术栈和你们学的完全不接 |
| 基于深度学习的垃圾图片分类 / 基于 YOLO 的目标检测 | 表面很酷，实际是"调包跑通 YOLOv8 官方 demo"，代码量可能只有 200 行，**软件工程的过程与文档完全写不满**，而且答辩老师一问"你改了什么"就露馅 |
| 物联网在智能交通中的应用研究 | 是"研究"，通常要硬件（Arduino/树莓派/摄像头），实验室不一定给板子 |
| 电影推荐系统（协同过滤+深度学习）| 大概率全年级撞题；"深度学习"部分对你们是纯调包 |

**结论**：原清单里安全的是 `新闻资讯 App`、`个性化博客平台`、`医疗保健 App` 这几个——但都太 CRUD，拿高分难。所以策略是：**保留一个稳妥题保交付，赌一个带硬核内核的题冲高分。**

## 一、新增选题 · A 组：JavaWeb + 算法内核（推荐度最高）

### A1. 课程作业查重与代码相似度检测平台的设计与实现 ⭐ 最推荐
- **做什么**：教师建作业 → 学生批量上传源码/文档 → 系统两两比对 → 生成相似度矩阵热力图 + 逐行高亮对照报告 → 教师裁定并归档。
- **硬核点（非 CRUD）**：
  1. 源码处理：剥注释/字符串 → 词法分析 → token 归一化 → **Winnowing 指纹算法**（k-gram + 哈希 + 滑窗取最小）计算相似度；
  2. 文档文本：分词 + **SimHash** 海明距离；
  3. 图片作业：**感知哈希 pHash** 比对；
  4. 性能：1000 份作业两两比对是 O(n²)，必须做**指纹倒排索引**把候选集压下来——这就是报告里"性能优化"章节的素材。
- **C/C++ 怎么用**：核心指纹算法用 C++ 写成一个独立命令行模块（`fingerprint.exe`），Java 侧用 `ProcessBuilder` 调用并解析 JSON 输出。这样**报告里就有了"C++ 高性能计算模块 + Java 业务层"的架构图**，比纯 Java 有说服力得多。
- **技术栈**：Spring Boot + MySQL + Vue/Element-UI + C++ 算法模块。
- **难度**：★★★★（算法有难度，但每个算法都有公开论文和现成 Java/C++ 参考实现）
- **参考项目**：fanghon/antiplag（代码/文档/图片相似度查重，中文注释）：https://github.com/fanghon/antiplag
- **为什么适合你们**：需求分析（教师/学生/管理员三角色）清晰，用例图、类图、时序图能画满；算法部分有对比实验（不同 k 值、不同阈值下的准确率），论文/报告天然有"实验与分析"章节。

### A2. 高校智能排课与考试安排系统的设计与实现
- **做什么**：录入教师/班级/教室/课程/时间约束 → 自动生成无冲突课表 → 人工拖拽微调 → 导出 Excel → 考试周自动安排考场。
- **硬核点**：把排课建模成 **CSP（约束满足问题）**——硬约束（同一教师同一时段不能两处、教室容量≥人数、连堂）与软约束（上午优先、避免连上四节）分离；用**遗传算法/模拟退火**求解，前端画出**适应度收敛曲线**；无法完全满足时给出"冲突最小化"的降级方案。
- **技术栈**：Spring Boot + MySQL + Vue + ECharts（收敛曲线）。
- **难度**：★★★★
- **参考项目**：
  - panorama-jack/Course-Arrangement（遗传算法排课）：https://github.com/panorama-jack/Course-Arrangement
  - wuchenge/CourseArragement（Java+SpringBoot+Vue 排课，工程结构可参考）：https://github.com/wuchenge/CourseArragement
- **答辩优势**：能把"算法参数调优实验"讲成故事，老师最爱听。

### A3. 基于大模型与向量检索的课程资料智能问答平台（RAG）的设计与实现
- **做什么**：上传课件 PDF/PPT/教材 → 自动解析分块 → 向量化入库 → 学生提问 → 混合检索召回 → 大模型生成回答并**标注引用来源（第几页第几段）** → 教师后台维护知识库。
- **硬核点（都不是调包就完事）**：
  1. **分块策略对比实验**：固定长度 vs 按段落 vs 按标题层级，测召回率；
  2. **混合检索**：BM25（关键词）+ 向量（语义）加权融合，可调权重；
  3. **引用溯源**：回答里带原文片段，解决大模型幻觉，这是产品化的关键；
  4. 无答案时主动拒答（阈值判定）。
- **技术栈**：Spring Boot + MySQL（+ pgvector/Milvus 或简化为本地向量文件）+ Vue + 大模型 API（DeepSeek/智谱均有免费额度）。
- **难度**：★★★★（不用训练模型，纯工程 + 检索算法）
- **参考项目**：
  - buoluonei/course_rag（课程资料 RAG 问答）：https://github.com/buoluonei/course_rag
  - xiongQvQ/ready_tensor_chatbot_rag（LangChain + ChromaDB 思路参考）：https://github.com/xiongQvQ/ready_tensor_chatbot_rag
- **注意**：这是"学生版 RAG"，比补充篇里的普通"问答助手"高一档，因为多了检索算法与实验设计。

### A4. 校园实验室设备预约与耗材管理系统（带冲突调度）
- **做什么**：实验室/设备预约、耗材申领、设备报修、二维码签到、库存预警。
- **硬核点**：多设备多时段的**区间冲突检测与调度**（时间片模型 + 回溯搜索，而非简单查 SQL 有无重复）；预约满时进入**等待队列并自动补位**；设备生命周期状态机（可用/借出/维修/报废）；耗材库存低于阈值自动生成采购申请。
- **技术栈**：Spring Boot + MySQL + Vue。
- **难度**：★★★
- **参考项目**：
  - giteecode/laboratoryAppointPublic（实验室预约，含论文+PPT）：https://github.com/giteecode/laboratoryAppointPublic
  - YuLin-Coder/No155LaboratoryManagementSystem（实验室+设备+耗材）：https://github.com/YuLin-Coder/No155LaboratoryManagementSystem
- **提醒**：参考项目很多，**务必自己加冲突调度和状态机这两个模块**，否则就是纯 CRUD，会被问到哑口无言。

### A5. 自习室 / 图书馆座位预约与短时锁定系统
- **做什么**：地图式选座 → 预约 → 到馆扫码签到 → 暂离/离馆 → 违约记录。
- **硬核点（全在"并发与一致性"上）**：
  1. **短时锁定防超卖**：选座后锁 5 分钟，超时释放（Redis 过期 key 或数据库乐观锁 `version` 字段）；
  2. **候补队列**：满座时排队，有人退座自动通知；
  3. **信用分模型**：多次爽约降权、限制预约；
  4. **并发压测**：用 JMeter 模拟 500 人同时抢座，对比"悲观锁 / 乐观锁 / Redis 预扣"三种方案的吞吐量——**报告里直接出数据表格**。
- **技术栈**：Spring Boot + MySQL + Redis + Vue/小程序。
- **难度**：★★★
- **答辩优势**：老师一问"并发怎么办"，你能拿出实测数据，这是大多数课设没有的。

### A6. 校园视频点播与课程回放平台的设计与实现
- **做什么**：替代老师清单里的"视频展示系统"，但技术含量高一个档次：教师上传 → 自动转码 → 播放 → 弹幕/笔记 → 学习进度统计。
- **硬核点**：FFmpeg **异步转码任务队列**（不能同步阻塞请求）+ 失败重试；转码为 **HLS（.m3u8 + .ts 切片）**实现拖动秒开；**断点续播**记录播放位置；防盗链（签名 URL + 时效）；播放完成度分析。
- **技术栈**：Spring Boot + MySQL + Redis + Vue + FFmpeg。
- **难度**：★★★★
- **参考**：可搜 GitHub `springboot video HLS`；FFmpeg 命令行封装即可，无需 C++ 功底。

### A7. 面向大学生的 AI 记账与消费画像系统
- **做什么**：拍照/语音记账 → OCR 识别小票 → 自动分类（餐饮/交通/学习）→ 月度消费画像与预算预警。
- **硬核点**：小票 OCR 结果**结构化解析**（正则 + 规则引擎从一堆乱文本里抽出金额、商家、时间）；消费分类用规则 + 大模型兜底；预算预警用移动平均预测下月支出；消费画像用 ECharts 雷达图。
- **技术栈**：Spring Boot + MySQL + Vue/小程序 + 百度 OCR API（免费额度）+ 大模型 API。
- **难度**：★★★
- **参考项目**：
  - GystuG/LiteNote（AI 记账，语音/拍照/AI 对话记账）：https://github.com/GystuG/LiteNote
  - ngoubimaximillian12/Expense-tracker-ai（OCR 小票扫描 + 去重）：https://github.com/ngoubimaximillian12/Expense-tracker-ai

### A8. 基于多维分析的校园学业预警与数据看板系统
- **做什么**：导入成绩/考勤/借阅/上网日志 → 清洗入库 → 多维分析看板 → 挂科风险预警名单 → 辅导员跟进记录。
- **硬核点**：**ETL 数据清洗流程**（脏数据、缺失值、异常值处理要有文档）；OLAP 式多维下钻（学院→专业→班级→个人）；风险预测**手写逻辑回归或加权评分卡**（不必上深度学习，报告里写清"为什么不用神经网络：样本量不足/可解释性要求"——这本身就是加分点）；导出预警报表。
- **技术栈**：Spring Boot + MySQL + Vue + ECharts。
- **难度**：★★★
- **参考项目**：
  - handsomeyaqiang/SchoolBigDataAnalysis：https://github.com/handsomeyaqiang/SchoolBigDataAnalysis
  - Elsayed-Elsherbiny/Student-Performance-Behavior（学生行为与成绩相关性分析）：https://github.com/Elsayed-Elsherbiny/Student-Performance-Behavior

## 二、新增选题 · B 组：C / C++ 系统向（发挥你们学过的 C/C++）

> 这一组的价值：**全班大概率都在写 JavaWeb 管理系统，你做系统编程，撞题率接近零，答辩老师会高看一眼。**
> 风险：进度不如 CRUD 可控，**必须一开始就把范围砍到最小**（下面每个都给了"最小可行版本"）。

### B1. 局域网即时通讯与文件传输系统的设计与实现
- **做什么**：C++ 编写的 Windows 客户端 + 服务端，支持一对一/群聊、在线状态、离线消息、大文件传输。
- **硬核点**：自定义应用层协议（消息头定长 + 消息体变长，解决 TCP **粘包/拆包**）；服务端 **select / IOCP** 多路复用；多线程 + 线程池；**文件分块传输 + 断点续传 + SHA-256 校验**；心跳保活与断线重连。
- **技术栈**：C++17 + Winsock/Asio + SQLite（消息存储）+ Qt 或控制台客户端。
- **最小可行版本**：单人聊天 + 文本消息 + 1 个群 + 文件传输（不要求断点续传）。
- **难度**：★★★★
- **参考**：搜 GitHub `C++ chat room socket`、muduo 网络库（学习 Reactor 模型思想，不必直接用）。

### B2. 高性能轻量 HTTP 服务器与静态资源托管系统（附性能对比实验）
- **做什么**：C++ 实现 HTTP/1.1 服务器：解析请求行/头/体、支持 GET/POST、静态文件、Keep-Alive、目录索引、简易 CGI。
- **硬核点**：**Reactor 事件循环 + epoll(ET) + 线程池 + 定时器（处理超时连接）**；用 **wrk / ApacheBench 压测**，与 Tomcat 对比 QPS 和延迟；给出优化前后（单线程 → 多线程 → epoll）的对比曲线。
- **技术栈**：C++17 + Linux/虚拟机（WSL2 也行）+ WebBench/wrk。
- **难度**：★★★★
- **答辩优势**：**天然自带性能实验数据**，这是软工课设里最稀缺的东西。
- **参考**：搜 GitHub `C++ web server epoll`（TinyWebServer 一类的教学项目很多），但**必须自己重写并做压测实验**。

### B3. 基于内容分块的秒传与增量同步网盘系统
- **做什么**：文件上传下载 + 断点续传 + 秒传 + 多端增量同步。
- **硬核点**：**内容定义分块（CDC）或固定分块** → 每块算 SHA-256 → 服务端只存已存在的块（**秒传**）；客户端只上传差异块（**rsync 思想**）；并发分块上传与合并校验；大文件内存占用控制（流式处理，不能一次性读进内存）。
- **技术栈**：C++/Java 客户端 + Spring Boot 服务端 + MySQL + 本地文件系统/MinIO。
- **难度**：★★★★
- **亮点**：讲清楚"为什么改一个字节不需要重传整个文件"，是一个能讲 5 分钟的漂亮技术点。

### B4. 数据结构与算法可视化教学平台的设计与实现
- **做什么**：学生在网页写/选一段代码（排序、链表、二叉树、最短路、并查集）→ 后端执行并**记录每一步的执行轨迹** → 前端单步动画回放 + 复杂度对比。
- **硬核点**：**执行轨迹采集**——C/C++ 用宏/插桩输出状态快照，或 Java 用字节码/解释器方式跟踪；轨迹序列化成 JSON 事件流；前端按事件驱动动画（不是录视频）；支持时间轴拖动。
- **技术栈**：C++/Java 后端 + Vue + Canvas/SVG 动画。
- **难度**：★★★★★（**建议裁剪到只做 6 个经典算法**）
- **参考项目**：
  - youngwinds/data-structure-visualization：https://github.com/youngwinds/data-structure-visualization
  - saoud30/VisuAlgo：https://github.com/saoud30/VisuAlgo
- **加分理由**：教学工具，成果可直接给学院用，容易写"应用价值"。

### B5. C 语言子集编译器 / 解释器的设计与实现
- **做什么**：实现一个能编译/执行 C 语言子集的程序：支持变量、算术与逻辑运算、if/while、函数调用、数组。
- **硬核点**：**词法分析（DFA）→ 递归下降语法分析（AST）→ 语义检查 → 三地址码生成或直接树遍历求值**；错误定位与友好报错；附语法图与测试用例集。
- **技术栈**：C++ 或 Java 均可（Java 更好写）。
- **难度**：★★★★
- **提醒**：适合组里有 1–2 个对编译原理/底层感兴趣的强手；**界面演示效果弱**，要在演示上多下功夫（做一个 Web 在线编译器前端就好很多）。

## 五、怎么"包装"一个选题让它显得高质量（方法论）

任何一个题目，只要加上下面其中**两条**，就从"管理系统"变成"有技术含量的系统"：

1. **加一个算法内核** —— 推荐（协同过滤）、排课（遗传算法）、查重（Winnowing/SimHash）、调度（冲突检测/队列）、匹配（以图搜图）。*纯 Java 就能写，不需要新语言。*
2. **加一个 AI 能力，但只调 API** —— OCR、语音转写、大模型、内容审核。Java 官方 SDK 十几行代码，风险低、听起来高级。
3. **加一个非功能约束** —— 并发一致性（乐观锁/Redis）、性能压测（JMeter/wrk 出数据）、安全（JWT + 权限 + SQL 注入防护）、可观测性（日志/监控）。**这一条是课设里最稀缺、最容易拿高分的。**
4. **加一个实验对比章节** —— 两种算法/两种锁/两种分块策略的对比数据 + 图表。老师看的是"你验证了什么"，不是"你用了什么框架"。
5. **换场景避撞题** —— "电影推荐"→"校园活动推荐"，"垃圾图片分类"→"失物以图搜图"，同样的技术，不同的题，没人跟你重。

## 六、4–5 人分工怎么落到纸面（对应第一张幻灯片的 6 种角色）

| 角色 | 负责的交付物 | 建议承担的模块 |

## 七、避坑清单
