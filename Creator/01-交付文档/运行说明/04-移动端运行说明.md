## 一、形态总览

## 三、Android APK 构建与分发

> **当前版本 1.0.2（versionCode 3）· 2026-10-17**
> - **1.0.1 白屏修复**：1.0.0 因生产构建把 element-plus 拆成 a/b 两个 chunk 触发跨 chunk 循环
>   （`Cannot access 'ge' before initialization`），装到真机上是**整屏米色白屏**；已在 `vite.config.js` 修掉
>   （记录见 `Creator/02-过程资料/03-迭代记录/06-收尾/99-修复记录.md` F-11/F-12）。
> - **1.0.2 状态栏/平板适配**：`targetSdk 35` 在 Android 15 强制 edge-to-edge，WebView 会画到状态栏下面——
>   前端补了顶部安全区（`--safe-top`），原生侧加 `adjustMarginsForEdgeToEdge: "force"`，
>   状态栏/窗口底色改米色；同时把移动断点提到 1024、触屏平板按单栏渲染（F-14）。
> **升级注意**：1.0.0 在 WebView 里注册过 Service Worker，覆盖安装后旧 SW 会继续回放旧缓存导致仍然白屏——
> **必须先卸载旧版再装 1.0.x**（或"设置→应用→存储→清除数据"）。1.0.1 起 APK 已不含 SW（mobile 模式不注入 PWA），
> 之后版本可直接覆盖安装。

**本机已配置**（一次性）：Android cmdline-tools + platform-35/build-tools 35（`lost-found/_android-sdk/`）、Gradle 8.11.1 走腾讯镜像、依赖走阿里云镜像、签名 `frontend/android/app/lostfound.keystore`（口令 shiguang2026，课程演示用）、品牌图标 mipmap 全分辨率、明文白名单见下。

**标准构建流程**（Windows 全程可做）：

```bash
cd frontend
npx vite build --mode mobile --outDir dist --emptyOutDir   # 烙入 .env.mobile 的后端地址
npx cap copy android                                       # dist → android 资产（只同步 web 资源）
cd android && ./gradlew.bat assembleRelease                # 首次约 4 分钟，增量约 1 分钟
# 产物：app/build/outputs/apk/release/app-release.apk
# 复制为 backend/uploads/downloads/app-release.apk 即完成分发（后端按请求读盘，无需重启）
```

**构建要点 / 踩坑**：
- 工程在「软件工程」中文目录下，Gradle 会把 junction 解析回真实路径，因此不依赖联接目录，
  改为 `android/gradle.properties` 里 `android.overridePathCheck=true`（实测 aapt2 可用）。
- `cap copy` 前先确认 `frontend/dist` 是**移动版**（`--mode mobile`），否则会烙进 localhost 的接口地址。
- 本地验证 APK 资产能否渲染：用静态服务器指向 `android/app/src/main/assets/public`，
  并在浏览器里注入 `window.androidBridge`（`@capacitor/core` 据此判定原生，等价于 Capacitor 容器）。
- 版本号在 `android/app/build.gradle` 的 `versionCode/versionName`；每次分发前 +1，便于覆盖安装与识别。
- **mobile 构建不注入 PWA/SW**（`vite.config.js` 按 mode 判断）：APK 里资源本来就在包内，SW 只会在升级后回放旧缓存。

**分发**：把 `app-release.apk` 复制为 `backend/uploads/downloads/app-release.apk` → 官网（WelcomeView 底部）"📱 下载 Android 版"按钮即生效（`GET /api/file/apk`）。手机允许"未知来源安装"后直接安装。

**明文 HTTP 取舍（重要）**：`app/src/main/res/xml/network_security_config.xml` 已做——**全局禁明文**（满足"release 构建 cleartext 关闭"红线），仅对课程演示的局域网后端 IP `10.140.76.101` 放行。后端 IP 变了要同步改这个文件；生产上 HTTPS 后删除该 domain-config。

**安装验收（真机）**：允许未知来源 → 安装 → **顶部导航不再压状态栏** → 登录 → 📸 拍照 → 以图搜图 → 发布；杀 App 重开登录态还在（Preferences）；8MB 原图经 1600px/q70 压缩后上传 ≤5MB。

## 四、iPhone（方案 C：PWA 保底）

已接入 `vite-plugin-pwa`（manifest：standalone + 品牌图标 192/512 + autoUpdate SW）；`index.html` 补 apple-touch-icon 与 iOS meta。iPhone 用 **Safari** 访问站点 → 分享 → **添加到主屏幕**，即得独立图标、全屏启动的"App"（无需签名、不过期）。首次访问官网时 iOS Safari 会显示安装引导浮层（可关闭，本会话不再打扰）。

**没有 Mac 时的路线到此为止**；有 Mac + 付费账号可按原 Prompt 方案 A 上 TestFlight（代码层已备好，`npx cap add ios` 即可）。

## 五、已知边界

- 局域网 HTTP：仅演示白名单 IP 明文；上公网必须 HTTPS（Creator/01-交付文档/12）。
- 校园网 DHCP IP 变动：需同步改 `.env.mobile`、`network_security_config.xml`，并重打包。
- PWA 离线壳：SW 预缓存了前端资源，后端不可达时页面可打开但数据报错（属预期，联调以在线为准）。
- **状态栏（F-14）**：Android 15 + targetSdk 35 会强制 edge-to-edge。1.0.2 用「CSS 安全区 + 原生 `adjustMarginsForEdgeToEdge:"force"` + 状态栏米色」三重兜底；
  若某台设备的 WebView 既不认 `env()` 也不走原生边距，表现为顶部仍压一点点——把机型告我，改读原生 inset。
- **升级路径**：1.0.0 → 必须先卸载（旧 SW）；1.0.1 起可覆盖安装。版本号看「设置→应用→校园失物招领」。
