# E-08（P3·后端/部署，可选）工程加固：图片防盗链、管理端 CSV 导出、水印顺序红线

> E 批第 8 条（共 8 条）。**可选项**，且三项相互独立，可任选子项执行。总览与公共红线见 `00-索引与执行顺序.md` 及本文末尾。

## 现象与证据

1. **图片无防盗链**：`/uploads/**` 由 `WebMvcConfig.java:28` 裸静态映射，无 Referer 校验；UUID 路径属弱防护，任何人拿到链接可外链引用。
2. **无数据导出**：管理端只有 `GET /api/admin/db-counts` 行数自检（`AdminController.java:80`），无 CSV/Excel 导出，答辩演示"数据沉淀"时缺一手材料。
3. **水印**：当前无水印。若做，存在**必须先算 pHash 后加水印**的顺序红线（见修复要求 3）。

## 修复要求

### A. 防盗链（推荐 Nginx 层，不改应用代码）

- 在 `01-交付文档/12-部署手册` 的 Nginx 配置节补 `valid_referers` 白名单示例（放行本站与空 Referer），并说明单机内网部署下这是最合理位置；应用层 `WebMvcConfig` **不改**（避免影响本地直连开发与 test_api 的图片路径断言）。
- 若执行方坚持应用层实现：只允许在新增的独立拦截器中做，且必须默认关闭（配置开关），`application-prod.yml` 示例开启——禁止直接改 `WebMvcConfig` 现有映射。

### B. 管理员 CSV 导出

- `GET /api/admin/export/items.csv`（role=1，与现有 admin 端点同鉴权口径）：导出 item 全量（id、类型、名称、分类、地点、状态、审核状态、发布人、时间），流式写出，`Content-Disposition` 带文件名。
- **防 Excel 公式注入**：单元格值以 `=`/`+`/`-`/`@` 开头时前置 `'` 转义（用户输入的标题/地点会进 CSV）。
- 数字口径：导出行数须与 `/api/admin/db-counts` 的 item 数一致，在 99-修复记录附两者对齐的证据。
- `01-交付文档/04` 补端点；`01-交付文档/01` FR6 可补一句"支持启事数据导出"。

### C. 水印（默认不做；要做必须遵守顺序红线）

- ⚠️ **顺序红线**：pHash 必须基于**加水印前**的原图计算并入库。若先加水印再算哈希，后续 `reindex`/`regen-thumbs`（`POST /api/search/reindex`）会基于带水印文件重算，指纹漂移、历史比对结果失真——这是以图搜图核心链路，宁可不加水印也不能踩。
- 若执行：水印在 FileStorageService 落盘时加（角落半透明文字，`java.awt` 即可），同时**把"原图保留 or 只留水印图"的取舍**写进 01-交付文档/06 与部署手册；并更新 `01-交付文档/11` 实验报告的方法说明（实验用的原始图未加水印，结论边界不变但注明）。

## 验收标准

```bash
# A：按部署手册配置 Nginx 后 curl -H "Referer: http://evil.com" -I <图片URL> → 403；本站引用 200
# B：管理员登录导出 → 行数 = db-counts.item；含 = 开头标题的启事导出后单元格被转义
# C：加水印后 POST /api/search/reindex → indexed-count 与加水印前一致（哈希不漂移）
```
