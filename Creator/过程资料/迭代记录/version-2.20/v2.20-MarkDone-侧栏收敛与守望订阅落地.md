#### 2.3.4 命中推送链路

```
管理员审核通过一条招领 (auditStatus 0→1)
  └─ AdminService.auditItem → watchService.matchOnApprove(item)
       ├─ 取 item_image.phash（只处理 type=found）
       ├─ 取所有 status=1 且未过期、且不属于发布者的守望位
       ├─ dist = min(Long.bitCount(target.phash ^ item.phash))
       ├─ dist ≤ 该守望人方案的阈值 → 插一条 message(type=watch, refId=itemId)
       └─ 更新守望位 hit_count / last_hit_item_id
```

- 只在**审核通过**时比对：待审内容不外泄，也符合「新招领入库」的语义。
- 守望失败被 `try/catch` 包住，只记 `WARN`，不影响审核主流程。
- 通知标题带相似度（`守望命中 · 相似度 100%`），正文带守望备注与启事标题；点击「查看启事」直接进详情。
- 通知归入「系统通知」分栏（`NotificationsView` 的 system 过滤天然覆盖 `type=watch`），侧栏角标同步。

### 2.4 R4 右栏折叠把手固定到右上角（v2.20.1 补丁）

**改动文件**：`frontend/src/components/AppShell.vue`

**问题**：`.rail-toggle` 原来是 `position: absolute; left: -14px; top: 50%`，参照物是整列 `.rail-col`（高度 = 页面内容高度）。页面一长，50% 就落在首屏之外，滚动时还会跟着整列上下跑，表现为「按钮在右侧中间、滚一下就找不到了」。

**修复**：

```css
.rail-toggle {
  position: fixed;
  top: 14px;
  right: calc(max(0px, (100% - 1240px) / 2) + 14px);   /* 跟随居中壳体的右边缘 */
  width: 34px; height: 34px; border-radius: 50%;
  z-index: 100;
}
```

- `fixed` 相对视口定位，页面上下滚动时位置恒定（不再受 `.rail-col` 高度影响）。
- 只用 `right` 一个公式解决两档宽度：视口 > 1240 时贴住居中壳体的右边缘（`(100% - 1240px)/2`），≤1240 时距视口 14px；不会在宽屏上飘到浏览器最右侧。
- 尺寸从 28×64 的竖药丸改为 34×34 圆形，和移动端 `m-burger`（36×36 / 10px 圆角）同一量级；白底 + `0 2px 10px` 阴影，压在右栏推广卡深色底上也读得出「浮层控件」。
- `.rail-col.closed .rail-toggle svg { rotate(180deg) }` 保留：收起后图标翻转，点一下重新展开；`v-if="showRail"` 仍只让首页/失物墙/详情出现把手，`≤1080px` 一并隐藏。
- **前提**：`.rail-col` 及其祖先不能加 `transform/filter/perspective/contain`，否则 `fixed` 会改为相对该祖先定位（页面切换的 `page` 过渡只作用在中栏视图上，不影响这里）。

### 2.5 R5 首页右栏滚动时保持位置（v2.20.2 补丁）

**改动文件**：`frontend/src/components/AppShell.vue`、`frontend/src/components/FeedRail.vue`

**现象**：首页中间信息流往下滚，右栏（推广卡 / 找回战报 / 热门启事）跟着整列滚出视口，下方留出一大片空白；`FeedRail` 上写的 `position: sticky; top: 0` 形同虚设。

**实测（1440×900，滚到 800px）**：

| 状态 | `rail.top` | `rail` 计算样式 | 表现 |
|---|---|---|---|
| 修复前 | **-800** | `sticky`（在 `.rail` 上） | 整列跟着页面滚走，右侧留白 |
| 修复后 | **0** | `relative`（sticky 在 `.rail-col` 上） | 钉在视口顶部，内部照常独立滚动 |

**根因**：两层叠加——

1. `.rail` 的父级 `.rail-clip` 有 `overflow: hidden`（用于折叠动画时裁掉 300px 宽的内容）。`overflow` 会生成一个**永不滚动的滚动容器**，`position: sticky` 只能相对它生效，于是 sticky 实际上没有行程。
2. `.rail-col` 本身只有 100vh 高（`.rail` 是 100vh），即使不被裁剪，父级也没有足够的滚动区间让 sticky 走完整个信息流。

**修复**：

```css
/* AppShell.vue：sticky 上移到外壳 */
.rail-col { position: sticky; top: 0; height: 100vh; width: 300px; }

/* FeedRail.vue：内层只负责撑满 + 独立滚动 */
.rail { position: relative; width: 300px; height: 100%; overflow-y: auto; }
```

- `.rail-col` 是 grid item，sticky 的约束矩形是整行（高度 = 信息流高度），所以能一路钉住；`height: 100vh` 让它占满一屏。
- `.rail-clip` 的 `overflow: hidden` 保留——折叠动画仍需要它裁掉溢出的 300px 内容；sticky 已经不在它内部，不会被它影响。
- 折叠逻辑、把手位置、右栏内部滚动（`overscroll-behavior: contain`）都不受影响。

## 五、注意事项（后续改这块必看）

1. **导航选中态不要再写回 `--cream-deep`**：选中项必须用 `--nav-pill`，否则在浅灰轨道上会「陷下去」而不是「浮起来」；暗色的亮度关系与亮色相反，改动时两套令牌一起看。
2. **`subscribe` 落库必须用 `UpdateWrapper` 显式 `set`**：MyBatis-Plus 的 `updateById` 默认跳过 `null` 字段，降档到轻守时 `expire_time` 会残留上一次付费档的日期（本次联调就踩到了：接口返回 `null`，重新读又是旧日期）。`WatchService.persistPlan()` 是唯一落库入口，不要再改回 `updateById`。
3. **只在审核通过时反查**：不要把 `matchOnApprove` 挪到 `publish`，否则待审启事会通过通知泄露；也不要在事务外调用，否则命中记录可能先于审核结果落库。
4. **守望反查异常必须吞掉**：`AdminService` 里已有 `try/catch + WARN`，去掉会让一次通知失败把整个审核回滚。
5. **阈值语义**：守望位用的是各方案阈值（10/12/14），与以图搜图页的全局阈值（`application.yml` 的 12）不是同一个来源；以图搜图仍用 `image-search.hamming-threshold`。
6. **`img_url` 的清理在事务后置**：`removeTarget` 用 `TxUtil.afterCommit` 删缩略图；直接删会出现「库回滚了但文件没了」。
7. **演示环境没有支付**：页面页脚与文案都写明了；若以后接支付，`subscribe` 需要改成「下单 → 回调 → 落权益」，不要把现在的直接生效当成支付成功。
8. **开关只在当前这张照片上有效**：换图会重置为关，别把 `watchOn` 做成跨图片的全局状态。
9. **折叠把手是 `fixed`，不要再改回 `absolute + top: 50%`**：`.rail-col` 的高度等于内容总高度，50% 会落在首屏外，滚动时还会跟着跑。若以后给 `.rail-col` 或 `.shell` 加 `transform/filter/perspective/contain`，`fixed` 会退化成相对该祖先定位，右上角就失效了。
10. **把手用 `max()` 而不是 `100% - 620px`**：`right: calc(max(0px, (100% - 1240px)/2) + 14px)` 同时覆盖「视口比壳体宽」和「视口比壳体窄」两种情况，改壳体宽度（现 1240）时记得同步这个数字。
11. **右栏的 sticky 必须挂在 `.rail-col` 上，不要挂回 `.rail`**：`.rail-clip` 的 `overflow: hidden` 是折叠动画必需的裁剪层，但 `overflow` 会生成滚动容器，里面的 sticky 只相对它生效（它永不滚动）→ 右栏会跟着页面滚走。要改就改外壳。
12. **`.rail` 的 `height` 保持 `100%`**：外壳已 `100vh`，内层再用 `100vh` 会让两者高度脱节；`.rail` 只负责撑满与 `overflow-y: auto`。
