## 一、老师清单分析与结论策略

| 老师原题 | 结论 | 原因 |
|---|---|---|
| 基于 iOS 的电商 APP / 动漫播放器 / 视频展示系统（3 题） | ❌ 排除 | 需要 macOS + Xcode + Swift/OC，环境和技术栈双重卡死 |
| 物联网在智能交通中的应用研究 | ❌ 排除 | 偏硬件/综述，软件产物不足，实验室不一定给板子 |
| 基于用户体验的淘宝店铺设计研究 | ❌ 排除 | 编码量撑不起 4-5 人分工 |
| 基于深度学习的垃圾图片分类系统 | ❌ 不推荐 | 实质是"调包跑 demo"，代码量约 200 行，**软件工程的过程与文档写不满**，答辩一问"你改了什么"就露馅 |
| 基于协同过滤与深度学习的电影推荐系统 | ⚠️ 可做但慎选 | 大概率全年级撞题；若选，"深度学习"部分用 DL4J 或手写小网络（自实现反而是答辩亮点），避免纯调包 |
| 基于 YOLO 的目标检测与计数系统 | ⚠️ 需改造 | 纯调包版不推荐；改造为 **C++ 推理 + JavaWeb 管理端**（见选题 27）或新场景业务闭环 |
| 基于 Android 的医疗保健 App | ⚠️ 需换视角 | 开源参考少、需求敏感；建议做成"AI 心理树洞"新视角（见选题 14） |
| 基于 Android 平台的新闻资讯 App | ✅ 可做 | Android 主语言就是 Java，工作量可控（见选题 18） |
| 个性化博客平台设计与实现 | ✅ 可做 | 100% 纯 JavaWeb，靠增量功能撑新颖度（见选题 16） |
| 基于 C# 的建材类仓储账务一体化系统 | 🔒 极限保底 | C# 与 Java 同语法族，WinForms + MySQL 约一周上手；但要新学一门语言且新颖度最低 |

**结论策略**：原清单安全项（新闻 App、博客平台）都太 CRUD，拿高分难。所以策略是——**保一个稳妥题确保交付，赌一个带算法/系统内核的题冲高分**。

## 二、选题总库（合并去重后共 27 个，按梯队排序）

### 第一梯队 · 首推（新颖度、可行性、文档友好度平衡最好）

**1. 课程作业查重与代码相似度检测平台的设计与实现** ⭐ 冲高分首选
- **做什么**：教师建作业 → 学生批量上传源码/文档 → 系统两两比对 → 生成相似度矩阵热力图 + 逐行高亮对照报告 → 教师裁定归档。
- **硬核点（非 CRUD）**：① 源码剥注释/字符串 → 词法分析 → token 归一化 → **Winnowing 指纹算法**（k-gram + 哈希 + 滑窗取最小）；② 文档用分词 + **SimHash** 海明距离；③ 图片作业用 **pHash** 比对；④ 1000 份作业两两比对是 O(n²)，必须做**指纹倒排索引**压缩候选集——报告"性能优化"章节的现成素材。
- **C/C++ 怎么用**：核心指纹算法写成 C++ 命令行模块（`fingerprint.exe`），Java 用 `ProcessBuilder` 调用解析 JSON——报告里就有了"C++ 高性能计算模块 + Java 业务层"架构图。
- **技术栈**：Spring Boot + MySQL + Vue/Element-UI + C++ 算法模块。**难度：★★★★**
- **参考**：fanghon/antiplag（代码/文档/图片查重，中文注释）：https://github.com/fanghon/antiplag
- **为什么适合你们**：教师/学生/管理员三角色，用例图类图时序图画满；不同 k 值、阈值下的对比实验天然构成"实验与分析"章节。

**2. 校园失物招领平台的设计与实现（以图搜图）** ⭐ 平衡型首选
- **做什么**：失物/招领发布 + 关键词匹配；核心亮点"以图搜图"——上传失物照片自动匹配历史相似图片（感知哈希 pHash，纯 Java 几十行）。
- **新颖点**：拍一张水杯能匹配出之前登记的同款，演示惊艳且零 Python 依赖、零 API 依赖。
- **技术栈**：Spring Boot + MySQL + Vue/小程序 + JImageHash（纯 Java 感知哈希库）。**难度：★★★**
- **参考**：
  - JImageHash：https://github.com/KilianB/JImageHash
  - 314love/shiwu：https://github.com/314love/shiwu ｜ bsxj02/lost-and-found-system：https://github.com/bsxj02/lost-and-found-system
  - 前端模板：vue-element-admin：https://github.com/PanJiaChen/vue-element-admin

**3. 高校智能排课与考试安排系统的设计与实现**
- **做什么**：录入教师/班级/教室/课程/时间约束 → 自动生成无冲突课表 → 人工拖拽微调 → 导出 Excel → 考试周自动安排考场。
- **硬核点**：排课建模为 **CSP 约束满足问题**——硬约束（同一教师同时段不能两处、教室容量、连堂）与软约束（上午优先、避免连上四节）分离；用**遗传算法/模拟退火**求解，前端画**适应度收敛曲线**；无解时给出"冲突最小化"降级方案。
- **技术栈**：Spring Boot + MySQL + Vue + ECharts。**难度：★★★★**
- **参考**：
  - panorama-jack/Course-Arrangement（遗传算法排课）：https://github.com/panorama-jack/Course-Arrangement
  - wuchenge/CourseArragement（Java+SpringBoot+Vue）：https://github.com/wuchenge/CourseArragement
- **答辩优势**：算法参数调优实验能讲成故事，老师最爱听。

**4. 基于大模型与向量检索的课程资料智能问答平台（学生版 RAG）的设计与实现**
- **做什么**：上传课件 PDF/PPT → 自动解析分块 → 向量化入库 → 学生提问 → 混合检索召回 → 大模型生成回答并**标注引用来源（第几页第几段）** → 教师后台维护知识库。
- **硬核点**：① **分块策略对比实验**（固定长度 vs 按段落 vs 按标题层级，测召回率）；② **混合检索**：BM25 关键词 + 向量语义加权融合，权重可调；③ **引用溯源**解决大模型幻觉；④ 无答案时主动拒答（阈值判定）。
- **技术栈**：Spring Boot + MySQL（向量检索可简化为本地向量文件）+ Vue + 大模型 API（DeepSeek/智谱免费额度）。**难度：★★★★**
- **参考**：
  - buoluonei/course_rag：https://github.com/buoluonei/course_rag
  - xiongQvQ/ready_tensor_chatbot_rag（LangChain + ChromaDB 思路参考）：https://github.com/xiongQvQ/ready_tensor_chatbot_rag
- **简化变体**：不做向量检索，用 MySQL 全文检索 + 关键词分类，做成"校园办事指南智能问答平台"，难度降到 ★★，仍成立。

### 第二梯队 · JavaWeb + 算法/AI 内核

**5. 校园实验室设备预约与耗材管理系统（带冲突调度）**
- **做什么**：设备预约、耗材申领、报修、二维码签到、库存预警。
- **硬核点**：多设备多时段**区间冲突检测与调度**（时间片模型 + 回溯搜索，不是简单 SQL 查重）；预约满进**等待队列自动补位**；设备生命周期**状态机**；耗材低于阈值自动生成采购申请。
- **技术栈**：Spring Boot + MySQL + Vue。**难度：★★★**
- **参考**：giteecode/laboratoryAppointPublic（含论文+PPT）：https://github.com/giteecode/laboratoryAppointPublic ｜ YuLin-Coder/No155LaboratoryManagementSystem：https://github.com/YuLin-Coder/No155LaboratoryManagementSystem
- **提醒**：务必自己加冲突调度和状态机模块，否则就是纯 CRUD。

**6. 自习室/图书馆座位预约与短时锁定系统**
- **做什么**：地图选座 → 预约 → 扫码签到 → 暂离/离馆 → 违约记录。
- **硬核点（全在并发与一致性）**：① **短时锁定防超卖**（选座锁 5 分钟，Redis 过期 key 或数据库乐观锁 version 字段）；② **候补队列**自动通知；③ **信用分模型**约束爽约；④ **JMeter 压测** 500 人抢座，对比悲观锁/乐观锁/Redis 预扣吞吐量——报告直接出数据表格。
- **技术栈**：Spring Boot + MySQL + Redis + Vue/小程序。**难度：★★★**

**7. 校园视频点播与课程回放平台的设计与实现**
- **做什么**：教师上传 → 自动转码 → 播放 → 弹幕/笔记 → 学习进度统计（替代老师清单"视频展示系统"，高一档）。
- **硬核点**：FFmpeg **异步转码任务队列** + 失败重试；**HLS（.m3u8 + .ts 切片）**拖动秒开；**断点续播**；防盗链（签名 URL + 时效）。
- **技术栈**：Spring Boot + MySQL + Redis + Vue + FFmpeg 命令行封装。**难度：★★★★**
- **参考**：GitHub 搜 `springboot video HLS`。

**8. 面向大学生的 AI 记账与消费画像系统**
- **做什么**：拍照/语音记账 → OCR 识别小票 → 自动分类 → 月度消费画像与预算预警。
- **硬核点**：小票 OCR 结果**结构化解析**（正则 + 规则引擎抽出金额/商家/时间）；分类用规则 + 大模型兜底；**移动平均预测**下月支出做预算预警；ECharts 雷达图画像。
- **技术栈**：Spring Boot + MySQL + Vue/小程序 + 百度 OCR API（免费额度）+ 大模型 API。**难度：★★★**
- **参考**：GystuG/LiteNote：https://github.com/GystuG/LiteNote ｜ ngoubimaximillian12/Expense-tracker-ai：https://github.com/ngoubimaximillian12/Expense-tracker-ai

**9. 基于多维分析的校园学业预警与数据看板系统**
- **做什么**：导入成绩/考勤/借阅/上网日志 → ETL 清洗入库 → 多维分析看板 → 挂科风险预警名单 → 辅导员跟进。
- **硬核点**：**ETL 清洗流程**（脏数据/缺失值/异常值处理写成文档）；OLAP 式多维下钻（学院→专业→班级→个人）；风险预测**手写逻辑回归或加权评分卡**（报告写清"为什么不用神经网络：样本量不足/可解释性"本身就是加分点）。
- **技术栈**：Spring Boot + MySQL + Vue + ECharts。**难度：★★★**
- **参考**：handsomeyaqiang/SchoolBigDataAnalysis：https://github.com/handsomeyaqiang/SchoolBigDataAnalysis ｜ Elsayed-Elsherbiny/Student-Performance-Behavior：https://github.com/Elsayed-Elsherbiny/Student-Performance-Behavior

**10. 基于协同过滤的校园活动报名与推荐平台的设计与实现**
- **做什么**：社团活动发布/报名/签到 + 个性化推荐；推荐算法用 Java 手写"基于用户的协同过滤"（评分表相似度计算，200 行以内，数据库组员深度参与）。
- **新颖点**：替代老师的"电影推荐"避免撞题；数据自造自控；冷启动问卷 + 热度兜底有话可写。
- **技术栈**：Spring Boot + MySQL + Vue。**难度：★★**
- **参考**：MovieLens 数据集可导入当测试数据：https://grouplens.org/datasets/movielens/

**11. 基于协同过滤与深度学习的电影推荐系统（Java 全栈路线）**
- **做什么**：MovieLens 数据入库，协同过滤 + 深度模型混合推荐，偏好标签可视化、推荐解释、冷启动策略。
- **语言映射**：Spring Boot + MyBatis + MySQL；协同过滤纯 Java；"深度学习"二选一——路线 A：**DL4J**（Java 深度学习库，14257★）搭 NeuralCF/MLP；路线 B：**手写反向传播小神经网络**（几百行，论文写"自实现深度模型"，反而是答辩亮点，C/C++ 功底正好用上）。
- **风险**：全年级撞题概率高（老师清单原题）；DL4J Maven 拉包多。选它前先打探其他组动向。**难度：★★★**
- **参考**（详见附录仓库表）：pq-dong/movierecommend（201★，最贴合的 Java 二开基座）、HongZhaoHua/jstarcraft-example（165★）、deeplearning4j-examples（2505★）。

**12. 基于 OCR 云服务的智能错题本系统的设计与实现**
- **做什么**：拍照 → 百度 OCR API（Java SDK）识别题目 → 按科目/章节/知识点归类 → 大模型 API 生成讲解和相似题 → 导出 PDF 复习。
- **新颖点**：AI + 教育热点；"AI 部分"只是两个 API 调用；组员自己就是用户，需求分析好写。
- **技术栈**：Spring Boot + MySQL + Vue/小程序 + 百度 OCR Java SDK + 大模型 API。**难度：★★★**

**13. 基于语音识别云服务的课堂录音纪要助手的设计与实现**
- **做什么**：课堂/会议录音上传 → 讯飞语音转写 API（Java SDK）转文字 → 大模型 API 生成摘要、提取待办和知识点 → 纪要管理与检索。
- **新颖点**：语音 AI 赛道，实现层面是两个 API 调用 + 一个管理后台。
- **技术栈**：Spring Boot + MySQL + Vue + 讯飞 SDK + 大模型 API。**难度：★★★**

**14. 基于情感分析的 AI 心理树洞小程序的设计与实现**
- **做什么**：匿名倾诉 + 情绪识别（大模型 API 打情绪标签）+ 情绪曲线记录 + 危机关键词自动提示心理中心热线 + 心理文章推送。对应老师清单"医疗保健 App"方向的新视角。
- **注意**：界面注明"仅作情绪陪伴，不构成诊疗建议"。
- **技术栈**：Spring Boot + MySQL + 微信小程序 + 大模型 API。**难度：★★**

**23. 局域网即时通讯与文件传输系统的设计与实现**
- **做什么**：C++ Windows 客户端 + 服务端，一对一/群聊、在线状态、离线消息、大文件传输。
- **硬核点**：自定义应用层协议（解决 TCP **粘包/拆包**）；**select/IOCP** 多路复用；线程池；**文件分块 + 断点续传 + SHA-256 校验**；心跳保活断线重连。
- **最小可行版本**：单人聊天 + 文本消息 + 1 个群 + 文件传输（不做断点续传）。
- **技术栈**：C++17 + Winsock/Asio + SQLite + Qt 或控制台。**难度：★★★★**
- **参考**：GitHub 搜 `C++ chat room socket`；muduo 网络库（学 Reactor 思想，不必直接用）。

**24. 高性能轻量 HTTP 服务器与静态资源托管系统（附性能对比实验）**
- **做什么**：C++ 实现 HTTP/1.1：请求解析、GET/POST、静态文件、Keep-Alive、目录索引、简易 CGI。
- **硬核点**：**Reactor 事件循环 + epoll(ET) + 线程池 + 定时器**；用 **wrk/ApacheBench 压测**与 Tomcat 对比 QPS/延迟；给出单线程→多线程→epoll 优化前后对比曲线。
- **答辩优势**：天然自带性能实验数据，课设里最稀缺。**难度：★★★★**
- **参考**：GitHub 搜 `C++ web server epoll`（TinyWebServer 一类教学项目），**必须自己重写并做压测**。

**25. 基于内容分块的秒传与增量同步网盘系统**
- **做什么**：上传下载 + 断点续传 + 秒传 + 多端增量同步。
- **硬核点**：**内容定义分块（CDC）**→ 每块 SHA-256 → 服务端只存已有块（**秒传**）；客户端只传差异块（**rsync 思想**）；流式处理控制内存。
- **技术栈**：C++/Java 客户端 + Spring Boot 服务端 + MySQL/MinIO。**难度：★★★★**

**26. 数据结构与算法可视化教学平台的设计与实现**
- **做什么**：学生选一段代码（排序/链表/二叉树/最短路/并查集）→ 后端执行并**记录执行轨迹** → 前端单步动画回放 + 复杂度对比。
- **硬核点**：执行轨迹采集（插桩输出状态快照）→ JSON 事件流 → 前端事件驱动动画（非录视频）+ 时间轴拖动。**建议裁剪到只做 6 个经典算法**。
- **技术栈**：C++/Java 后端 + Vue + Canvas/SVG。**难度：★★★★★**
- **参考**：youngwinds/data-structure-visualization：https://github.com/youngwinds/data-structure-visualization ｜ saoud30/VisuAlgo：https://github.com/saoud30/VisuAlgo
- **加分理由**：教学工具可直接给学院用，"应用价值"好写。

**27. 基于 YOLO 的目标检测与计数系统（C++ 推理路线，改造老师原题）**
- **做什么**：C++ 推理服务（**ONNX Runtime + OpenCV** 直接加载现成 yolov8n.onnx，**不需要自己训练/导出**）+ JavaWeb 管理端（视频/设备管理、计数报表、告警大屏）。
- **场景**：课堂人数清点 / 校园路口车流 / 食堂排队监测，选一个讲故事。
- **风险**：Windows 下 OpenCV C++ 环境配置（用预编译库或 vcpkg）；答辩用录播视频兜底实时性。**难度：★★★★**
- **参考**：UNeedCryDear/yolov8-opencv-onnxruntime-cpp（452★）https://github.com/UNeedCryDear/yolov8-opencv-onnxruntime-cpp ｜ JustasBart/yolov8_CPP_Inference_OpenCV_ONNX（98★，纯 OpenCV DNN，依赖最少）https://github.com/JustasBart/yolov8_CPP_Inference_OpenCV_ONNX

## 五、"包装"方法论：让任何题目显得高质量

任何题目，加上下面**任意两条**，就从"管理系统"变成"有技术含量的系统"：

1. **加一个算法内核**——推荐（协同过滤）、排课（遗传算法）、查重（Winnowing/SimHash）、调度（冲突检测/队列）、匹配（以图搜图）。纯 Java 就能写，不需要新语言。
2. **加一个 AI 能力，但只调 API**——OCR、语音转写、大模型、内容审核。Java 官方 SDK 十几行代码，风险低、听起来高级。
3. **加一个非功能约束**——并发一致性（乐观锁/Redis）、性能压测（JMeter/wrk 出数据）、安全（JWT + 权限 + SQL 注入防护）、可观测性（日志/监控）。**这一条是课设里最稀缺、最容易拿高分的。**
4. **加一个实验对比章节**——两种算法/两种锁/两种分块策略的对比数据 + 图表。老师看的是"你验证了什么"，不是"你用了什么框架"。
5. **换场景避撞题**——"电影推荐"→"校园活动推荐"，"垃圾图片分类"→"失物以图搜图"，同样的技术，不同的题，没人跟你重。
