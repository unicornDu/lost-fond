# E-04（P2·后端+前端）用户个人主页 /user/:id：发布人可点击，公开信息脱敏

> E 批第 4 条（共 8 条）。总览与公共红线见 `索引与执行顺序.md` 及本文末尾。依赖 E-01（头像/资料字段），建议在其后执行。

## 现象与证据

1. **无个人主页路由**：`frontend/src/router/index.js` 无 `/user/:id`；`DetailView.vue` 的发布人只渲染纯文本 `item.owner`，不可点击——用户无法查看"TA 还发布了什么"，跨启事找同一失主的场景走不通。
2. **无对应后端接口**：`UserController` 仅有 stats/messages 端点，无他人资料查询。

## 修复要求

1. **后端两个只读端点**（登录可见即可，游客沿用现有"游客不可用主功能"口径）：
   - `GET /api/users/{id}/profile` → `{id, nickname, avatar, createTime, itemCount}`。守卫：用户不存在 404；**已封禁用户返回 404**（不向外界暴露封禁名单，也不渲染被封禁者主页）。
   - `GET /api/users/{id}/items` → 分页，**只返回前台可见口径的启事**（audit_status=1 且 status ∈ 寻找中/待认领/认领申请中/已找回/已认领；已下架/已关闭不可见——与列表接口 ItemService 的可见性守卫口径一致，直接复用同一套过滤条件，不要另写一份口径）。
2. **隐私脱敏（重要）**：公开主页**不返回 `account`（学号）**。学号属身份信息，SRS 仅允许在认领审核场景（FR5.3）对发布者可见；个人主页泄露学号等于泄露登录账号。nickname/avatar/createTime/发布列表即可。
3. **前端**：
   - 新路由 `/user/:id` + `UserProfileView.vue`：头像、昵称、加入时间、TA 的发布（复用 ItemCard 网格 + 分页）；
   - `DetailView.vue` 发布人文本改为可点击链接进入主页；
   - 若他人查看自己的主页，显示"这是我的主页"标识（可复用 profile 跳转）。
4. **单测 + 回归**：不存在用户 404；封禁用户 404；items 端点不含已下架启事（先下架再查，制造缺口再验证——红线 7 的证伪要求）；返回体断言**不含 account 字段**。`test_api.py` 补鉴权负向。
5. **文档同步**：`Creator/01-交付文档/04` 两个端点；`Creator/01-交付文档/01` FR1.4 或 FR4.2 补一句"可查看发布者主页（公开信息）"；router 表在项目结构文档（`Creator/01-交付文档/运行说明/项目结构.md`）如有路由清单则同步。

