# 需求规格说明书（SRS）v1.0

> 交付物编号 01（成员B）。项目：拾光 · 基于感知哈希的校园失物招领平台。

## 1. 引言

### 1.1 目的与范围
本文档定义校园失物招领平台"拾光"的功能与非功能需求。系统解决传统失物招领"文字描述搜不准"的痛点，核心特性为**以图搜图**：上传物品照片，基于 64 位感知哈希（pHash）与汉明距离匹配全校失物/招领启事。

### 1.2 用户角色
| 角色 | 说明 |
|---|---|
| 游客 | 浏览落地页（不可用主功能） |
| 注册用户 | 发布/浏览/检索启事、以图搜图、申请认领、私信、收消息 |
| 发布者（用户的一种） | 审核收到的认领申请（查看凭证后通过/拒绝） |
| 管理员 | 后台：审核启事、下架/删除、封禁用户、看统计、看操作日志 |

### 1.3 术语
pHash、汉明距离、JWT、审核流水位（audit_status）、状态机（见 02/06）。

## 2. 功能需求（M1–M6）

### FR-1 用户模块（M1）
- FR1.1 注册：6-12 位数字学号 + ≥6 位口令（BCrypt 入库），学号唯一；注册即登录（发 JWT）。
- FR1.2 登录：校验口令；连续错 5 次锁 10 分钟；"记住我"决定 token 有效期（30 天/1 天）。
- FR1.3 会话：令牌置 `Authorization: Bearer`；被封禁账号即使持有效令牌也按未登录处理（`/auth/me` 例外：E-05 返回专用码 40301 供前端展示封禁提示）。
- FR1.5 账号自助管理（E-01）：修改密码（旧密码校验，新密码 6-32 位，改密后需重新登录）与资料编辑（昵称/头像/联系方式，即 user.phone）。
- FR1.4 个人中心：我的发布（含待审核标记）、我的认领、我的收藏（E-07）、收到的申请、消息通知、账号设置（E-01）；可查看发布者公开主页 `/user/:id`（E-04，仅昵称/头像/加入时间/公开启事，不含学号）。

### FR-2 发布模块（M2）
- FR2.1 发布寻物/招领启事：类型、名称(≤60)、分类(6 类)、地点、时间、描述(≤500)、图片 1–3 张（**必填**，≤5MB/张，jpg/png/gif/bmp/webp，魔数校验）。
- FR2.2 图片处理：落盘 `uploads/yyyy/MM/uuid.ext`；计算 64 位 pHash 入库；生成 480px 缩略图（列表用）。
- FR2.3 审核流水位：新发布进入"待审核"，管理员通过后前台可见/可搜。

### FR-3 以图搜图（M3，核心）
- FR3.1 上传查询图 → 计算 pHash → 与库内指纹逐条汉明距离（`BIT_COUNT(a^b)`）→ 距离 ≤ 阈值(12) 判相似 → 按相似度降序返回 Top-10（附相似度百分比与比对图数）。阈值与返回数经网格扫描标定（03 T-02，旧值 10/6，见 Creator/01-交付文档/11 §2.4：top-n=10/th=12 端到端召回 85.7% 且误检 0）。
- FR3.2 待审核/已下架/已关闭启事不参与检索。
- FR3.3 详情页提供"视觉相似"推荐（同算法最近邻）。
- FR3.4 匹配报告（P2）：搜图结果可一键固化为 PDF 报告（Top-N/相似度/比对参数），入交付体系。

### FR-4 检索模块（M4）
- FR4.1 列表按 类型/分类/地点/关键词(标题+描述)/排序(最新|最热) 组合筛选，分页（size ≤100）。
- FR4.2 详情：浏览量原子自增（同访客 30 分钟去重）、多图查看（可放大）。
- FR4.3 收藏（E-07）：登录用户可收藏/取消收藏公开可见启事（幂等），个人中心分页查看；启事删除时收藏级联清理。

### FR-5 认领与消息（M5）
- FR5.1 认领申请：须填"只有失主知道的特征"凭证（≤200 字）+ 可选联系方式；仅"寻找中/待认领"状态可申请；重复申请拦截。
- FR5.2 状态机：`寻找中/待认领 → 认领申请中 →（通过）已找回/已认领`；拒绝时若仍有其他"审核中"申请则保持"认领申请中"；通过时自动关闭同物品其余申请并通知。
- FR5.3 发布者审核时可看到申请人昵称/学号/凭证/联系方式（防盲审、防冒领）。
- FR5.4 站内消息：认领各节点通知；未读数（导航铃铛）；单条/全部已读；私信**支持双向回复**（E-03：消息带发送者，收信人可回复，回复同样带发送者，天然多轮）。
- FR5.5 交付文件（P1）：认领审核通过自动生成**认领证明 PDF** 交付双方；用户在消息中心交付卡片下载（浏览器内）；越权/穿越/超限受控（见 Creator/01-交付文档/04 受控下载路由）。

### FR-6 管理后台（M6）
- FR6.1 启事审核（通过/驳回，驳回可附理由）、违规下架（可附理由）、删除（连带清理图片与关联数据）；审核/下架结果站内通知发布者（E-02）。
- FR6.2 用户管理：搜索、封禁/解封（不可封管理员）。
- FR6.3 看板：总数/团聚数/成功率/用户数/近30天趋势/分类占比（ECharts）。
- FR6.4 操作日志留痕并分页可查；`reindex`/`regen-thumbs` 管理员工具；启事数据 CSV 报表（E-08B 引入，P1 起入交付体系统一受控下载，防公式注入）。

## 3. 非功能需求

| 编号 | 需求 | 指标/实现 |
|---|---|---|
| NFR-1 | 搜图响应 | < 2s（实测 avg 40ms：th=10/top-n=6 旧参数下测量；现行参数 th=12/top-n=10 见 Creator/01-交付文档/11 §2.4：41~54ms） |
| NFR-2 | 上传限制 | 单图 ≤5MB、请求 ≤20MB |
| NFR-3 | 并发 | 20 并发搜图全部成功、结果一致（实测总 132ms：th=10/top-n=6 旧参数下测量，现行参数见 Creator/01-交付文档/11 §2.4） |
| NFR-4 | 安全 | BCrypt 口令；JWT 鉴权+越权拦截（401/403）；SQL 预编译防注入；上传魔数校验；敏感配置外置不入库；登录限流 |
| NFR-5 | 可用性 | 关键流程有错误态与重试；404 兜底；移动端可导航 |
| NFR-6 | 数据 | 图片存文件系统（库只存路径+指纹）；备份方案（scripts/backup.sh） |
| NFR-7 | 接口规范 | 统一 `{code,msg,data}`；错误不泄露内部信息；接口文档 Knife4j |
| NFR-8 | 部署形态 | **单 Web**：后端托管 `frontend/dist`，浏览器同源访问（:8080），无客户端安装包；可选 cloudflared 临时公网演示 |
| NFR-9 | 构建可验证 | `npm run build` 产物必须可正常首屏渲染（F-11：dev 正常不代表 build 正常，发布前需冒烟） |

## 4. 约束与假设
- 部署形态：校园内网/单机部署（java -jar + Nginx 或后端直接托管 dist，见部署手册 12）；演示可经花生壳 HTTPS 穿透临时公网访问（1Mbps，需开 gzip）。
- 演示数据由 DataInitializer 幂等播种（60 启事/120 条图片引用（30 个去重文件）/认领/消息）。
- 以图搜图为"辅助匹配"：旋转/大裁剪场景存在算法边界（见报告 11），不承诺 100% 召回。
- 交付形态：单 Web。原 Android/桌面端已于 2026-10-17 下线（手册与产物归档于 `Creator/02-过程资料/03-迭代记录/06-收尾/archive-多端/`）。
