# E-01（P1·后端+前端）账号体系补全：修改密码 + 资料编辑 + 处置 user.phone 死字段

> E 批第 1 条（共 8 条）。总览与公共红线见 `索引与执行顺序.md` 及本文末尾。

## 现象与证据

账号体系只到"注册+登录"为止，用户没有任何自助管理能力：

1. **无修改密码接口**：`UserController` 全文无 password 相关端点；唯一密码入口是注册（`AuthController.register`）。
2. **无资料编辑接口**：无 `PUT /api/user/profile`；头像在注册时从 8 个 emoji 随机分配（`AuthService.java:34、52` 附近），之后不可更改；昵称注册后不可改。
3. **user.phone 是死字段**：`db/schema.sql:22` 建了 `phone VARCHAR(20) DEFAULT NULL COMMENT '联系电话（选填）'`，`entity/User.java:19` 映射了它，但**全代码库无任何读写**。认领申请里的"联系方式"填的是 claim_record.contact，与此字段无关。
4. **忘记密码无解**：前端"忘记密码"是占位按钮（见 E-06），后端也无重置通道——用户密码丢失即永久失联。

## 修复要求

1. **修改密码**：`PUT /api/user/password`，body `{oldPassword, newPassword}`。校验旧密码（BCrypt match），新密码沿用注册规则（≥6 位），BCrypt 入库。改密成功后**前端强制清 session 重新登录**（无服务端吊销机制，这是既定取舍，接口文档注明即可，不要为此加 token 黑名单）。
2. **资料编辑**：`PUT /api/user/profile`，body `{nickname?, phone?, avatar?}`。
   - 头像用**方案 A（推荐）**：前端从预设 emoji 头像列表中挑选，avatar 存 emoji 字符串（与现状存储方式一致，零文件管理成本）；如执行方想做成上传文件，需复用 `FileStorageService`（魔数校验、≤2MB、仅图片格式）并在 Creator/01-交付文档/06 补字段说明，二选一。
   - nickname 校验：非空、≤20 字（与注册侧现有校验对齐，先核对注册时的实际限制再写）。
   - **user.phone 一并启用**：放进 profile 编辑并允许在认领申请"联系方式"处快捷填入（前端），或者干脆从 schema + entity 中删列（DROP COLUMN 写进增量 SQL 并同步 Creator/01-交付文档/06）。**二选一，禁止保留"有字段无使用"现状**。
3. **前端**：`ProfileView.vue` 增加第 5 个 tab「账号设置」：改密码表单（旧密码+新密码+确认）、资料编辑表单（昵称/头像选择/手机号）、保存后刷新 user store（`stores/user.js`）与导航栏头像昵称。
4. **单测**：`UserService`（或落在 `AuthService`）新增用例：旧密码错 → 400；新密码 <6 位 → 400；正常改密 → BCrypt 可 match 新密码；profile 编辑读回一致。控制器层接口在 `scripts/test_api.py` 补鉴权负向断言（未登录 401）。
5. **文档同步（红线 5）**：
   - `Creator/01-交付文档/04` 新增两个端点条目；
   - `Creator/01-交付文档/06` 若 phone 改动则同步数据字典；
   - `Creator/01-交付文档/01` FR1.4 补一句"支持修改密码与编辑个人资料（昵称/头像/联系方式）"。

