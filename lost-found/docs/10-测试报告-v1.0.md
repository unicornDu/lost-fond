## 3. 覆盖率说明

- 接口：6 模块 **24 个端点全部**被自动化覆盖（05 A-02 补齐此前漏测的 register / mark-found / offline / regen-thumbs 四个端点；含正向+鉴权负向+参数边界）。
- 状态机：认领"通过/拒绝/竞争申请/重复审核/非法状态申请"5 条迁移路径全覆盖（TC-竞争-01/02、TC-M5-02/04/05/06），并由 ClaimServiceTest 9 用例做单元级回归（05 A-03）。
- 幂等性：test_api 连跑多轮，**item / item_image / message 回基线**（经 `/api/admin/db-counts` 自检，05 A-01）；**admin_log 为审计日志、设计上只增不减，不计入幂等基线**（脚本结尾打印本轮增量留痕）。
- 未自动化部分：前端 18 条手工用例（导航/404/竞态/移动端），已按清单逐条走查通过。

## 4. 遗留问题与说明

| 项 | 说明 |
|---|---|
| pHash 对旋转/大裁剪失效 | 算法固有边界，报告 11 已量化（旋转10°/裁剪70% 三种哈希召回均≈0）；缓解=多图入库+拍摄引导，列入展望 |
| JWT 无服务端吊销 | 设计取舍：无状态换取扩展性；封禁实时性已通过拦截器查库解决，登出=前端清 token（报告已注明） |
| 错误响应统一 HTTP 200+code | 既定契约，接口文档已注明取舍 |

系统在功能、状态机、安全（鉴权/越权/上传/注入）、性能四个维度均通过测试；9 个真实缺陷全部闭环且转化为防回归断言。**建议进入验收答辩阶段。**
