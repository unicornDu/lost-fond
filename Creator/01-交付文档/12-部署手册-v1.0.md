# 拾光 · 部署手册（含审查 2.42 三连坑）v1.0

> 交付物 1.4。覆盖：生产打包、Nginx 托管、以及三个必踩坑的规避。

## 一、打包

```bash
# 后端（用环境变量 MAVEN_HOME / JAVA_HOME，不硬编码绝对路径 —— 审查 2.42③）
cd backend
"%MAVEN_HOME%\bin\mvn" clean package -DskipTests      # 产出 target/lost-found-backend.jar
# 前端
cd ../frontend
npm run build                                          # 产出 dist/
```

> **构建后必须冒烟（F-11 教训）**：`npm run dev` 正常 ≠ `npm run build` 正常。曾因 element-plus 被按组件首字母拆成
> a/b 两个 chunk、组件双向依赖跨 chunk 成环，生产包入口直接 `Cannot access 'xx' before initialization`，整站只剩背景色。
> 现在 element-plus 归一 chunk（973.6kB）+ echarts 独立；每次 `build` 后至少打开一次 `dist/index.html`（或 `npm run preview`）
> 确认首屏有内容、F12 无红色报错，再部署。

## 二、启动后端（固定工作目录 —— 审查 2.42②）

`file.upload-dir` 默认 `./uploads` 是**相对启动目录**的路径。换目录启动会另建空 uploads 导致图片 404。
两种规避（二选一）：
1. **固定工作目录**：永远在 `backend/` 目录下执行 `java -jar target/lost-found-backend.jar`；
2. **绝对路径/环境变量**：启动时 `--file.upload-dir=D:/lost-found/uploads` 或设 `UPLOAD_DIR` 环境变量（application.yml 已支持 `${UPLOAD_DIR:./uploads}`）。

生产关闭接口文档（审查 2.42①）：
```bash
java -jar target/lost-found-backend.jar --spring.profiles.active=prod
```
`application-prod.yml` 已设 `springdoc.api-docs.enabled=false`、`knife4j.enable=false/production=true`，此时 `/doc.html` 不可用（返回 404/被屏蔽）。

**静态资源压缩（F-11 配套）**：`application.yml` 已开 `server.compression`（text/html/css/js/json，>1KB 才压）。
前端产物约 1.6MB，公网穿透（1Mbps）不压缩首屏要 10s+，gzip 后约 450KB。
注意：**改了 yml 必须重打 jar 并重启**才生效（`java -jar` 读的是 jar 内配置）。

**后端同时托管前端（P3，可省掉 Nginx）**：`app.frontend-dist-dir` 默认 `../frontend/dist`（可 `FRONTEND_DIST_DIR` 覆盖），
`WebMvcConfig` 把 `/**` 映射到该目录 + `FrontendController` 做 SPA 回退。把 `dist` 与 jar 按目录结构放好，
浏览器直接访问 `http://host:8080` 即是完整站点（本机与花生壳穿透都用这套）。

## 三、Nginx 托管前端 + 反代后端

```nginx
server {
    listen 80;
    server_name lostfound.example.com;

    # 前端 dist（history 模式需 try_files 回退 index.html）
    root /var/www/lost-found/dist;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端接口反代
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # 修复 B-07：必须透传 X-Forwarded-For——后端已配 server.forward-headers-strategy: native，
        # 靠它还原真实客户端 IP；缺这行时匿名访客浏览量去重会退化成"全站共用一把 key"
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 20m;      # 与后端 multipart 上限一致
    }

    # 上传图片静态资源：可直接由 Nginx 读磁盘（性能更好），或反代给后端
    location /uploads/ {
        alias /var/www/lost-found/uploads/;   # 指向后端 upload-dir 同一目录
        expires 7d;
        # E-08A 图片防盗链（推荐在 Nginx 层做，不改应用代码）：
        # 放行本站域名与空 Referer（浏览器直接打开图片/部分客户端不带 Referer），其余 403
        valid_referers none blocked server_names
                       *.example.com example.com localhost;
        if ($invalid_referer) { return 403; }
    }
}
```

要点：
- `try_files ... /index.html` 必须加，否则刷新 `/wall` 等 history 路由会 404；
- `/uploads` 的 alias 目录要与后端 `file.upload-dir` 指向**同一物理目录**；
- `client_max_body_size` 不小于后端 `max-request-size`，否则大图被 Nginx 先拒（413）；
- **CORS（修复 Z-03）**：同源反代下前后端同源，不产生跨域，Nginx/后端都无需配 CORS 头；后端仅在 `web.cors.allowed-origins` 显式列出跨域来源时放行（生产 profile 默认为空 = 不放行；通配 + 凭证放行已移除，Bearer 鉴权无 Cookie 场景无收益）。
- **交付文件目录与中文字体（P1）**：`FileDeliveryService` 在 `uploads/deliveries/yyyy/MM/` 下落盘认领证明/报表/匹配报告，备份策略与 uploads 一致；PDF 生成依赖 CJK 字体（Windows 微软雅黑/黑体已满足；Linux 服务器需安装 `fonts-wqy-microhei` 或 Noto CJK 之一，否则生成时明确报错而非静默乱码）。
- **图片防盗链（E-08A）**：`/uploads/` 的 `valid_referers` 白名单如上示例（`server_names` 换成本站实际域名；`none`/`blocked` 放行空 Referer 以免误伤直接打开）。验证：`curl -H "Referer: http://evil.com" -I <图片URL>` 应 403，本站页面引用应 200。单机内网部署下这是最合理位置，应用层 `WebMvcConfig` 不做改动。

## 四、演示/答辩本机最简部署

不必 Nginx：后端 `java -jar`（:8080）**已能直接托管 dist**（见二），浏览器开 `http://localhost:8080` 即可；
开发热更才需要 `npm run dev`（:5173），或 `npm run preview`（:4173）看构建产物。
前端 dev/preview 的 `/api`、`/uploads` 代理已在 `vite.config.js` 配好。

**公网演示（花生壳免费穿透，P3 现用）**：本机 8080 → `https://131kt2646vt74.vicp.fun`。
要求：电脑不休眠 + 后端在跑 + 花生壳客户端在线；免费版 1Mbps/1GB 月流量，所以 gzip 必开、图片别太大。
桌面安装包与 APK 的发行地址分别烙在 `desktop/default-config.json` 与 `frontend/.env.mobile`，换域名两者都要改并重打包。

**移动端/桌面端分发**：APK 产物复制为 `backend/uploads/downloads/app-release.apk`（官网按钮 `GET /api/file/apk` 提供）；
桌面 `npm run dist` 产出 `release2/ShiGuang Setup x.y.z.exe`。详见 `Creator/01-交付文档/运行说明/移动端运行说明.md`、`桌面端运行说明.md`。
