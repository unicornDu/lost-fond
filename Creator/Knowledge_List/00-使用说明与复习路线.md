## 一、这套清单怎么用

这是一份**可勾选的自测清单**，不是阅读材料。用法：

1. 先按「第三节 按角色必读范围」找到自己的部分，**不必全员通读 8 份**。
2. 每个知识点都是一个 `- [ ]` 复选框：能**不看书、口头讲清**再打勾。
3. 讲不清的，回看该项下面标注的「在本项目」位置，直接翻代码或文档对照。
4. 答辩前用 `08-答辩题库与话术.md` 做**交叉提问**：两人一组，一人问一人答，答不上来的记回本文件。

> 核心原则：**老师追问的不是"你用没用到"，而是"为什么这么用、代价是什么"。**
> 所以每个知识点都要求你能说出：① 是什么 ② 项目里在哪 ③ 为什么这么选 ④ 局限/代价。

## 五、必须背下来的 12 个数字

| 数字 | 含义 | 出处 |
|---|---|---|
| **64** | pHash 指纹位数（BIGINT / long） | `PHashUtil`、`application.yml: bit-resolution` |
| **12** | 汉明距离阈值（判"同一物品"的红线） | `application.yml: hamming-threshold` |
| **10** | 搜图返回 Top-N 条 | `application.yml: top-n` |
| **85.7%** | 端到端召回 48/56，误检 0 | `Creator/01-交付文档/11` §2.4 |
| **41~54ms** | 现行参数下单张搜图耗时（120 图索引） | `Creator/01-交付文档/11` §2.4 |
| **8 / 47** | 八张表 / 47 个 REST 端点 | `Creator/01-交付文档/04`、`06` |
| **141 / 99 / 12** | 接口断言 / 后端单测 / 前端单测 | `07-测试计划`、`10-测试报告` |
| **91 / 32** | 测试用例数 / 缺陷数（P0 8、P1 19、P2 3、P3 2） | `08-测试用例表`、`09-缺陷跟踪表` |
| **5MB / 480px** | 上传大小上限 / 缩略图宽度 | `application.yml`、`FileStorageService` |
| **20 / 60 / 120** | 种子数据：20 用户 / 60 启事（4 条待审）/ 120 条图片引用 | `DataInitializer`、`manifest.json` |
| **30s** | 消息未读数前端轮询间隔 | `NavBar` |
| **5 次 / 10 分钟** | 登录失败限流（同账号） | `AuthService: MAX_FAIL` |

## 六、自测通过标准

能在**白板/白纸**上，不看资料画出下面 5 张图，且能边画边讲：

- [ ] **1. 系统架构图**：浏览器 → Vite :5173（代理）→ Spring Boot :8080 → MySQL :3306，图片落 `uploads/` 映射为 `/uploads/**`
- [ ] **2. 后端分层数据流**：HTTP → Controller → Service → Mapper → MySQL；返回 entity → VO → `Result{code,msg,data}` → JSON
- [ ] **3. 八表 ER 图**：user→item→item_image，item→claim_record→user，user→message/admin_log/favorite，item→delivery
- [ ] **4. 物品状态机**：寻找中/待认领 →（申请）认领申请中 →（通过）已找回/已认领；任意状态 → 已下架/已关闭
- [ ] **5. pHash 五步**：灰度 → 缩 32×32 → DCT → 取左上 8×8 低频 → 按均值二值化得 64 位

再加三条口头必答：

- [ ] 为什么 `BIT_COUNT(phash ^ q)` 而不是 `XOR`（`^` 是按位异或，`XOR` 是逻辑异或只返回 0/1）
- [ ] 为什么审核/下架过滤要放进 SQL（否则 LIMIT 名额被待审项占满导致漏结果）
- [ ] 为什么 pHash 不用 MD5（感知哈希要求"视觉相似则指纹相近"，密码学哈希差一字节就面目全非）

## 七、纪律提醒

1. **每人必须有自己的一块**能讲到代码级；其余部分能讲到"是什么+为什么"即可，不要人人都背全部。
2. **不要背结论，要背依据**。被问"阈值为什么是 12"时，答"报告 11 §2.4 网格扫描：top-n=6 只有 53.6%，top-n=10/th=12 达 85.7% 且误检 0，且 th=12 是 mild 组 pHash 的 F1 峰值"，比答"试出来的"强十倍。
3. **承认边界比硬圆更好**。老师问到旋转搜图时，答"pHash 对旋转不鲁棒，实验里旋转 5° 召回 0.33、10° 归零，这是 DCT 的空域旋转敏感性；工程缓解是多图入库 + 拍摄引导，彻底解决需旋转不变特征或 CNN 特征"——这是加分项，不是减分项。
