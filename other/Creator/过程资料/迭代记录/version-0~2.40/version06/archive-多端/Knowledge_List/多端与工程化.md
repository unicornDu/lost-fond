## 1. 四端总览（★必背一张表）

| 端 | 壳 | 页面源 | 路由 | 后端地址 | 登录态真源 |
|---|---|---|---|---|---|
| Web | 浏览器 | `http://host:8080`（后端托管 dist） | history | 同源相对路径 | localStorage |
| PWA | 浏览器 + 主屏幕 | 同上 | history | 同源 | localStorage |
| Android | Capacitor（WebView） | `https://localhost` | **hash** | `VITE_API_BASE` 构建时烙入 | **Capacitor Preferences** |
| 桌面 | Electron | `file://` | **hash** | `default-config.json` + 可改 | localStorage |

**核心答案（背这句）**：一套前端源码，差异只在**三点** —— **路由模式、资源地址、登录态持久化**；业务代码零分叉，适配集中在 `utils/desktop.js`。

## 2. Capacitor（Android）

**原理**：把打包好的静态资源塞进一个原生 App 的 WebView，通过**插件桥**调用原生能力（相机、文件、Preferences）。本质上仍是 Web 技术，只是"跑在壳里"。

**构建链（能背下来）**：

```bash
npx vite build --mode mobile --outDir dist --emptyOutDir   # ① 烙入 .env.mobile 的 VITE_API_BASE
npx cap copy android                                        # ② 静态资源同步进原生工程
cd android && gradlew.bat assembleRelease                   # ③ 出 app-release.apk
# ④ 复制为 backend/uploads/downloads/app-release.apk → 官网「下载 Android 版」
```

- [ ] 能说出三个构建步骤各自做什么
- [ ] 能解释"为什么后端地址要在**构建时**烙入"（WebView 里没有 Vite 代理，必须写死后端绝对地址；换后端要重新打包）
- [ ] 知道签名用 `android/app/lostfound.keystore`，**这个文件绝不能进公开仓库**（泄露=他人可冒名签名发版）

**两个坑（真踩过）**：

| 坑 | 现象 | 修法 |
|---|---|---|
| Service Worker 残留 | APK 覆盖安装后仍**白屏**：旧 SW 回放旧缓存 | 1.0.1 起 **APK 构建不注入 SW**，只有 Web/PWA 注入；老版本需先卸载 |
| 中文路径 | Gradle 在中文路径下构建失败 | 用 ASCII junction 或 `android.overridePathCheck=true` |

- [ ] 能解释"为什么 mobile 构建不注入 Service Worker"

## 4. Electron（桌面）

**三层结构（必答）**：

| 层 | 文件 | 职责 |
|---|---|---|
| 主进程 | `main.cjs` | 创建窗口、生命周期、**探活后端**、读写配置、IPC 处理 |
| 预加载 | `preload.cjs` | 通过 `contextBridge` **只暴露白名单 API** 给渲染层 |
| 渲染层 | `renderer/`（构建产物） | 就是我们的 Vue 应用 |

- [ ] 能解释 `contextIsolation: true` + `nodeIntegration: false` 的意义（渲染层不能直接摸 Node/文件系统，防 XSS 升级为任意代码执行）
- [ ] 能解释"为什么打开 PDF 走 IPC"（渲染层不接触文件系统，主进程拿路径调系统程序，安全边界清晰）
- [ ] 知道 `prepare-renderer.js` 是打包前置：把桌面配置构建进 `renderer/`
- [ ] 知道 `default-config.json` 里是**发行默认后端地址**（当前为花生壳公网域名），用户可改
- [ ] 能说出"探活"是什么（启动时探测后端是否可达，不可达给提示而不是白屏）

**追问**："Electron 打出来为什么几百 MB？" → 它把整个 Chromium + Node 运行时打包进去（`win-unpacked` 里能看到 `chrome_*.pak`、`ffmpeg.dll`、`icudtl.dat`）。这是"一套 Web 代码出桌面版"的代价；更轻的替代是 Tauri（用系统 WebView）。

## 5. 多端适配的三个具体问题

| 问题 | 现象 | 解决 |
|---|---|---|
| 路由 | `file://` / `https://localhost` 下 history 刷新 404 | 桌面/原生切 **hash 路由** |
| 资源 | `/uploads/x.jpg` 在原生端指向 WebView 自身 → 404 | `assetUrl()` 拼 `API_ORIGIN` |
| 登录态 | WebView 的 localStorage 可能被系统清理 | 原生端以 **Preferences** 为真源，localStorage 只做镜像 |
| 安全区 | Android 15 edge-to-edge 压住状态栏 | `--safe-top` + `adjustMarginsForEdgeToEdge: "force"`（F-14） |
| 相机 | Web 的 `<input file>` 在原生体验差 | `utils/native-camera.js` → `Camera.getPhoto`（quality 70 + width 1600 压缩） |

- [ ] 能说出至少四个适配点及其原因

## 6. 部署

### 6.1 单机部署（本项目实际用法）

```bash
# 后端打包
cd web-lostfond/backend && mvn package -DskipTests
java -jar target/lost-found-backend.jar --spring.profiles.active=prod

# 前端构建（产物交给后端托管）
cd web-lostfond/frontend && npm run build      # → dist/
```

- 后端 `/**` 直接托管 `frontend/dist`（`FRONTEND_DIST_DIR` 可覆盖）+ **SPA 回退**（`FrontendController`）
- 因此 `http://localhost:8080` 就是完整站点，**不需要额外部署 Nginx**

## 7. 工程加固（这批是"超出课程要求"的加分项）

| 措施 | 做了什么 | 防什么 |
|---|---|---|
| 上传魔数校验 | 文件头必须匹配 jpg/png/webp 真实签名 | 改后缀上传木马 |
| UUID 重命名 | 用户可控文件名全部丢弃 | 路径穿越、覆盖攻击 |
| 受控下载 | `delivery` 表 + `/api/file/download` 校验 `owner_id` | 越权下载、直链盗链 |
| 响应头 | `no-store`、`X-Content-Type-Options: nosniff`、CSP、UTF-8 文件名 | 缓存泄露、MIME 嗅探、XSS |
| CORS 收敛 | 只放行显式来源（含 `null` 给桌面 `file://`、`https://localhost` 给 Android） | 任意站点盗用接口 |
| 导出限流 | 报表/报告的生成与下载带额度与二次确认 | 批量拉数据 |
| 审计日志 | 管理端所有敏感操作写 `admin_log` | 事后追责 |
| 配置分离 | 口令/secret 只在 gitignored 的 `application-local.yml` | 密钥进仓库 |

- [ ] 能说出至少 5 条，并说清各防什么
