## 一、打包

```bash
# 后端（用环境变量 MAVEN_HOME / JAVA_HOME，不硬编码绝对路径 —— 审查 2.42③）
cd backend
"%MAVEN_HOME%\bin\mvn" clean package -DskipTests      # 产出 target/lost-found-backend.jar
# 前端
cd ../frontend
npm run build                                          # 产出 dist/
```

## 二、启动后端（固定工作目录 —— 审查 2.42②）

`file.upload-dir` 默认 `./uploads` 是**相对启动目录**的路径。换目录启动会另建空 uploads 导致图片 404。
两种规避（二选一）：
1. **固定工作目录**：永远在 `backend/` 目录下执行 `java -jar target/lost-found-backend.jar`；
2. **绝对路径/环境变量**：启动时 `--file.upload-dir=D:/lost-found/uploads` 或设 `UPLOAD_DIR` 环境变量（application.yml 已支持 `${UPLOAD_DIR:./uploads}`）。

生产关闭接口文档（审查 2.42①）：
```bash
java -jar target/lost-found-backend.jar --spring.profiles.active=prod
```
`application-prod.yml` 已设 `springdoc.api-docs.enabled=false`、`knife4j.enable=false/production=true`，此时 `/doc.html` 不可用（返回 404/被屏蔽）。

## 三、Nginx 托管前端 + 反代后端

```nginx
server {
    listen 80;
    server_name lostfound.example.com;

    # 前端 dist（history 模式需 try_files 回退 index.html）
    root /var/www/lost-found/dist;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端接口反代
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # 修复 B-07：必须透传 X-Forwarded-For——后端已配 server.forward-headers-strategy: native，
        # 靠它还原真实客户端 IP；缺这行时匿名访客浏览量去重会退化成"全站共用一把 key"
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 20m;      # 与后端 multipart 上限一致
    }

    # 上传图片静态资源：可直接由 Nginx 读磁盘（性能更好），或反代给后端
    location /uploads/ {
        alias /var/www/lost-found/uploads/;   # 指向后端 upload-dir 同一目录
        expires 7d;
    }
}
```

要点：
- `try_files ... /index.html` 必须加，否则刷新 `/wall` 等 history 路由会 404；
- `/uploads` 的 alias 目录要与后端 `file.upload-dir` 指向**同一物理目录**；
- `client_max_body_size` 不小于后端 `max-request-size`，否则大图被 Nginx 先拒（413）。

## 四、演示/答辩本机最简部署

不必 Nginx：后端 `java -jar`（:8080）+ 前端 `npm run preview`（:4173，读 dist）或继续 `npm run dev`（:5173）。
前端 dev/preview 的 `/api`、`/uploads` 代理已在 `vite.config.js` 配好。
